# Препроцессор структуры базы данных Pilot

Проект готовит типы и атрибуты для импорта в Pilot. Препроцессор преобразует исходную схему в плоскую таблицу, проверяет ссылки, уникальность, иерархию и именование, формирует реестры, отчёты об ошибках и предупреждениях, а также промты для дальнейшей обработки.

## Назначение

- Получить исходную схему из фиксированной папки.
- Преобразовать её в плоскую структуру типов и атрибутов.
- Проверить корректность данных.
- Сформировать реестры и итоговые отчёты.
- Подготовить промты и документацию проекта.

## Структура репозитория

```text
/
├─ docs/
│  ├─ Spec_Dispatcher.md
│  ├─ Audit_Report.md
│  └─ Spec_Optimization.md
├─ prompts/
├─ Mod_Structure.bas
├─ Mod_Assembler.bas
├─ CONTRIBUTING.md
├─ README.md
└─ .gitignore
```

- `docs` содержит спецификацию, аудит и техническое задание на оптимизацию.
- `prompts` содержит версии промтов; старые версии не удаляются.
- Модули VBA в формате .bas лежат в корне репозитория. Рабочие файлы данных, журналы и результаты генерации в репозиторий не сохраняются.

### Файлы дополнительных данных (папка `01_Исходные данные\04_Дополнительные данные`)
В эту папку можно складывать любые файлы, которые помогут ИИ-Генератору. Эти файлы упоминаются в блоке 3.4 промта.
**Как задать назначение файла (опционально):**
1. Создайте файл `Назначения_доп_данных.txt` (UTF-8) в этой папке.
2. Формат строк: `Имя_файла = Назначение`.
   Пример: `ГОСТ Р 10.00.00.05-2025.pdf = Стандарт ГОСТ для терминологии и структуры`
3. Если файла нет, макрос выведет только имена файлов.

### Настройки проекта (`project_settings.md`)

Файл `project_settings.md` — **рабочий файл настроек**, который читает код при
генерации промтов шагов. Это **не** `prompt_settings_template.md` (памятка);
рабочий файл создаётся из образца `prompts/project_settings.md.example`.

**Где искать (в порядке приоритета):**
1. `04_Промты\Шаблоны\project_settings.md` — **основное место**;
2. `project_settings.md` (в корне, рядом с `.xlsm`);
3. `Шаблоны\project_settings.md` (внешняя папка «Шаблоны»);
4. `04_Промты\project_settings.md`.

**Как заполнить:**
1. Скопируйте `prompts/project_settings.md.example` в
   `04_Промты\Шаблоны\project_settings.md`.
2. Ключи `{{СПИСОК_ВХОДОВ}}`, `{{ПРАВИЛО_ОБЪЕКТА}}`, `{{ФОРМАТ_РЕЕСТРОВ}}`,
   `{{ПРОТОКОЛ_ШАГА}}`, `{{МАРКЕРЫ}}` — заполните один раз вручную
   (примеры в образце).
3. Ключи `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}` и `{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}` —
   скопируйте из **блока 2** ответа ИИ на Промт №0
   (между `<<<FILE:project_settings_fragment.md>>>` и
   `<<<END:project_settings_fragment.md>>>`).
4. `{{ДЕКОМПОЗИЦИЯ_ШАГОВ}}` — **не задавать**: код соберёт сетку из
   `Шаги.txt`.

**Формат строки:** `{{КЛЮЧ}} = значение`. Многострочное значение —
повторением ключа (строки склеиваются). UTF-8 без BOM, регистр ключей
значим.

**Если файл отсутствует:** генерация промта **не блокируется**, но в
промте на месте 7 ключей появится явный маркер
`[НЕ ЗАПОЛНЕНО: {{КЛЮЧ}}]`, в лог — `[WARN] P002`. Риски: ИИ-Генератор
может выдумать GUID, создать дубль базового типа, выбрать неверный
приоритет источника, вывести реестры не в том формате.

**Отличие от `prompt_settings_template.md`:** шаблон — памятка
(в генерации промта **не участвует**, только включается в Readme); рабочий
файл — `project_settings.md`.

### Порядок работы с Промтом №0 (декомпозиция)

Применяется, когда `04_Промты\Шаги.txt` ещё нет.

1. **Создать папки проекта** (кнопка 1), проверить исходные данные (кнопка 2).
2. **Собрать плоскую таблицу** (кнопка 3) → `02_Подготовка схемы\Адаптированная_структура_*.xlsx`.
3. **Создать `project_settings.md`** (см. раздел «Настройки проекта») —
   скопировать образец `prompts/project_settings.md.example` в
   `04_Промты\Шаблоны\project_settings.md`. **Без этого** блок «Известные
   GUID» в Промте №0 будет пустым.
4. **Сделать промт следующего шага** (кнопка 7). Так как `Шаги.txt` нет —
   будет создан `04_Промты\Промт_шаг_00_Декомпозиция.md`.
5. **Загрузить промт в ИИ-Генератор.** Ожидаемый ответ — **ровно два
   блока**:
   - `<<<FILE:Шаги.txt>>> ... <<<END:Шаги.txt>>>`;
   - `<<<FILE:project_settings_fragment.md>>> ... <<<END:project_settings_fragment.md>>>`.
6. **Сохранить блок 1** → `04_Промты\Шаги.txt` (UTF-8 без BOM).
7. **Сохранить блок 2** → вставить в `04_Промты\Шаблоны\project_settings.md`
   (ключи `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}` и `{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}`).
8. **Сделать промт следующего шага** (кнопка 7) ещё раз → создаётся
   `Промт_шаг_01.md`.
9. **Проверить `Промт_шаг_01.md`:** блок 4 — таблица GUID (не
   `[НЕ ЗАПОЛНЕНО]`), блок 5 — список базовых типов, блок 10.2 — Enum/Object
   **без** `<Configuration>`.

**Если в блоке 2 ответа ИИ GUID выдуманы или таблица пустая** — значит,
`project_settings.md` не был создан на шаге 3, либо ИИ проигнорировал
запрет. Перегенерировать Промт №0 после создания `project_settings.md`.

### Как передать промт Генератору

Способ передачи зависит от того, **умеет ли ваш ИИ-Генератор читать приложенные файлы**. Ниже — два сценария.

#### Сценарий А — Генератор имеет доступ к файлам (рекомендуется)

1. **Приложите файл** `Промт_шаг_NN.md` (или `Промт_шаг_00_Декомпозиция.md`) к сообщению.
2. **Приложите файлы исходных данных** отдельно:
   - Схема — `Адаптированная_структура_*.xlsx`;
   - Описание — `*.docx`;
   - Конфигурация — `*.xml` (или `*.txt`);
   - Дополнительные данные (опционально) — файлы из `01_Исходные данные\04_Дополнительные данные`.
3. **Добавьте короткий комментарий** (пример):

    Загружаю Промт №0 (декомпозиция) и файлы исходных данных.
    Выполни инструкции из промта. Верни результат в виде трёх списков
    в формате, готовом для вставки в .md или .txt (см. раздел
    «Формат вывода» в промте). Не сокращай, не дроби списки,
    не добавляй markdown-разметку (блоки кода) внутри списков.

**Почему так:** файл передаётся без искажений; Генератор видит весь промт целиком; нет риска «потерять» часть при копипасте.

#### Сценарий Б — Генератор НЕ имеет доступа к файлам

1. **Приложите файл** `Промт_шаг_NN.md` к сообщению (как в сценарии А).
2. **Вставьте содержимое исходных данных** текстом в чат (в одном сообщении или несколькими — как удобно):
   - **Схема** — выгрузите лист «Адаптированная_структура» в **CSV** или **Markdown-таблицу** (не `.xlsx` — таблицы в чате ломаются);
   - **Описание** — скопируйте текст из `.docx`;
   - **Конфигурация** — скопируйте XML (или его релевантную часть).
3. **Добавьте комментарий** (пример):

    Загружаю Промт №0 (декомпозиция) и содержимое исходных данных
    (Схема, Описание, Конфигурация) ниже. Выполни инструкции из промта.
    Верни результат в виде трёх списков в формате, готовом для вставки
    в .md или .txt (см. раздел «Формат вывода»).
    Не сокращай, не дроби списки,
    не добавляй markdown-разметку (блоки кода) внутри списков.

    --- СХЕМА (CSV) ---
    <вставить CSV>

    --- ОПИСАНИЕ ---
    <вставить текст>

    --- КОНФИГУРАЦИЯ (XML) ---
    <вставить XML>

**Почему не копипаст промта в чат:** при вставке в чат формат ответа часто ломается (Генератор преобразует структуру в markdown-разметку, списки теряют вид). Файл этого избегает.

**Что важно в обоих сценариях:**
- Промт передаётся **файлом**, не копипастом.
- В комментарии явно указано: «верни результат в виде трёх списков в формате, готовом для вставки в `.md` или `.txt`».
- Если Генератор не читает файлы — исходные данные передаются **текстом** (CSV / Markdown / XML), а не `.xlsx`/`.docx`.

### Проверка результата от Генератора

Перед сохранением списков проверьте ответ:

| # | Что проверить | Ожидание |
|---|---|---|
| 1 | Список 1 (`Шаги.txt`) | Строки `NN\|Имя_папки`, разделитель — pipe `\|` |
| 2 | Список 2 (`project_settings_fragment.md`) | Только `{{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <имя>` (без таблицы GUID) |
| 3 | Список 3 (`reference_info`) | Справочно; в `project_settings.md` не включается |
| 4 | Внутри списков | **Нет** markdown-разметки (блоков кода) |
| 5 | Между списками | **Нет** текста (только один перевод строки) |

**Если что-то не так** — перезапросите: «Верни результат в виде трёх списков в формате, готовом для вставки в `.md` или `.txt`, без markdown-разметки внутри списков».

### Если Генератор сломал формат

Типичные симптомы и что делать:

| Симптом | Что произошло | Действие |
|---|---|---|
| Списки оформлены как блоки кода ` ``` ` | Генератор обернул содержимое в markdown-разметку | Перезапросить: «Убери ` ``` ` внутри списков — только plain text» |
| Вместо трёх списков — другие маркеры (`<<<...>>>`, заголовки) | Генератор добавил служебные символы | Перезапросить: «Верни ровно три списка, без маркеров и заголовков» |
| Список разорван на части | Генератор «сократил» длинный список | Перезапросить: «Верни список целиком; если не помещается — `TRUNCATED: <имя>` и остановись» |
| Между списками есть текст | Генератор добавил пояснения | Перезапросить: «Убери текст между списками» |
| В списке 2 затесались GUID/комментарии | Генератор смешал списки | Перезапросить: «В списке 2 — только строки `{{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <имя>`» |

Если после 2–3 перезапросов формат не восстановлен — **скопируйте содержимое вручную** (границы списков видны по формату строк) и сохраните файлы. Это допустимый fallback.
