# Правила работы с репозиторием

Документ описывает простые правила работы с репозиторием для участников и агентов.

## Ветки

1. Ветка `main` защищена. Прямой push запрещён.
2. Базовая рабочая ветка QWEN-Coder — `for-coder`.
3. QWEN-Coder создаёт PR на основе ветки `for-coder`.
4. Имя рабочей ветки: `for-coder/W<N>-<краткое-описание-латиницей>`. Пример: `for-coder/W5-optimize-assembler`.
5. Работа прямо в `for-coder` тоже допустима.

## Запросы на слияние

1. Запрос на слияние создаётся после завершения задачи.
2. Запрос на слияние должен указывать код задачи из `Spec_Optimization.md` или код задачи из плана работ.
3. Основание PR — `for-coder` или `for-coder/W<N>-…`, цель PR — `main`.
4. Имя запроса на слияние должно быть таким:

```text
[W<N>] <краткое описание на русском>
```

Пример:

```text
[W5] Оптимизация Mod_Assembler
```

5. В описании запроса на слияние нужно указать:

- идентификатор задачи, например `OPT-03`;
- код задачи из плана работ, например `W3` или `W4`;
- краткий список изменений;
- список проверок, которые подтверждают готовность.

## Авторство и ревью

1. Автор правок в файлах `*.bas` — QWEN-Coder.
2. Ревью запросов на слияние выполняет QWEN.
3. Ревью выполняется по чек-листу.

Чек-лист ревью:

- Указан идентификатор задачи.
- Изменения соответствуют задаче.
- Не затронута защищаемая рабочая логика.
- Нет бинарных файлов Excel.
- Журналирование идёт через единый служебный модуль.
- Новые ошибки имеют коды.
- Новые модули соответствуют структуре проекта.
- Промты добавлены как новые файлы, старые промты не удалены.

## Работа с промтами

1. Промты хранятся в папке `prompts`.
2. Новый промт добавляется отдельным файлом.
3. Старые промты не удаляются.
4. Для версионирования используется номер версии, дата или идентификатор задачи.

## Работа с кодом VBA

1. Код VBA обновляется через файлы `*.bas`.
2. Изменения попадают в репозиторий через ветки и запросы на слияние.
3. Не следует заменять файлы `*.bas` вручную в обход истории изменений.
4. После слияния запроса на слияние ответственность за согласованность кода несёт владелец соответствующей задачи.

## Связь задач

1. Каждый запрос на слияние должен быть связан с задачей.
2. Допускается указывать идентификатор задачи из `Spec_Optimization.md`, например `OPT-03`.
3. Допускается указывать код задачи из плана работ, например `W3`, `W4` или `W5`.
4. Если запрос на слияние закрывает несколько задач, их нужно перечислить в описании.
