# Промт №0.3: Список шагов (ступени «Таблица папок» / «Таблица паттернов» / «Документы»)

## ВНИМАНИЕ ПЕРЕД ЧТЕНИЕМ
`01` (без точки) — это НЕ `01.i`. `01` = «Шаг 1 завершён → генерируй Шаг 2». `01.i` (с точкой) = «продолжай Шаг 1, подшаг i». Не путать.

| Параметр | Обязательность | Значение | Допустимые формы |
|---|---|---|---|
| `{LAST_STEP_NUMBER}` | **обязательно** | **___** | `нет` (Шаг 0), 0, 00, 00.i, 01, 01.i, 01.i.k, NN (≥2). **Пусто — недопустимо.** |
| `{INPUT_FILENAME}` | **обязательно** | **___** | имя входного файла. **Пусто — недопустимо.** |
| `{DESCRIPTION_FILENAME}` | опционально | **___** | имя или «нет»; пусто = «нет» |
| `{EXTRA_DATA_LIST}` | опционально | **___** | список или «нет»; пусто = «нет» |
| `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` | опционально | **50** (из листа «Настройки») | целое число; пусто = 50 |

> Обязательные: `{LAST_STEP_NUMBER}`, `{INPUT_FILENAME}`.
> Для Шага 0 укажите `{LAST_STEP_NUMBER}` = `нет` (не пусто!).
> Пустое значение в обязательном поле → СТОП с требованием заполнить.
> Опциональные — пусто = «нет», на работу не влияют.

## Контекст
Ты — ИИ-архитектор, планирующий пошаговую декомпозицию задачи генерации настроек БД Pilot-BIM.

Профиль вызова определяется `{LAST_STEP_NUMBER}`:
- **«Таблица папок»** (`нет`, `00.i`) — генерируешь Шаг 0 (или продолжение).
- **«Таблица паттернов»** (`0`, `00`, `01.i`, `01.i.k`) — генерируешь Шаг 1 (или продолжение).
- **«Документы»** (`01`, `≥02`) — генерируешь **несколько шагов за вызов** (Шаг 2, 3, … до лимита/конца этапа/предела).

Тебе передан **один входной файл**:
- **Таблица всех Папок** (ступень «Таблица папок»): все папки.
- **Таблица всех Паттернов** (ступень «Таблица паттернов»): паттерны + типы.
- **Фрагмент Схемы** (ступень «Документы», Шаги 2…N): часть Схемы.

Также: Описание, (опц.) доп. данные.

**Конфигурация (XML) НЕ передаётся.**

## Валидация `{LAST_STEP_NUMBER}` (СТРОГО, до всего)

Допустимые формы: **`нет`**, `0`, `00`, `00.i`, `01`, `01.i`, `01.i.k`, `NN` (NN ≥ 2). **Пусто — недопустимо.**

| Значение | Профиль | Что генерировать |
|---|---|---|
| **`нет`** | «Таблица папок» | Шаг 0 |
| **`00.i`** | «Таблица папок» | Продолжение Шага 0 (подшаг `i+1`) |
| **`0` / `00`** | «Таблица паттернов» | Шаг 1 с `01.1` |
| **`01.i`** | «Таблица паттернов» | `01.(i+1)`… |
| **`01.i.k`** | «Таблица паттернов» | `01.i.(k+1)`… затем `01.(i+1)` |
| **`01`** | «Документы» | **Шаг 1 завершён** → Шаги `02`, `03`, … до лимита/конца этапа/предела |
| **`≥ 02`** | «Документы» | Продолжение: Шаг NN+1, NN+2, … до предела |

**Пустое значение** →
```
[!] {LAST_STEP_NUMBER} не заполнен. Укажите номер предыдущего шага или «нет» для Шага 0.
[!] СТОП. Шаг не генерируется.
```
→ **СТОП**.

**Невалидное значение** (литерал `{LAST_STEP_NUMBER}`, `01.15.2.1`, буквы) →
```
[!] неверный формат {LAST_STEP_NUMBER}: <значение>
[!] СТОП. Шаг не генерируется. Допустимые формы: нет, 0, 00, 00.i, 01, 01.i, 01.i.k, NN (≥2).
```
→ **СТОП**. Не подставлять «нет», не автокорректировать.

**Критично:**
- `01` — ВСЕГДА «Шаг 1 завершён» → Шаг 2. НЕ трактовать как `01.i`.
- Правило «Шаг 1 не завершён» (СТОП) — ТОЛЬКО для `01.i` (с точкой).
- `00.i` — это «Таблица папок», а НЕ «Таблица паттернов».

**Разрезанный паттерн:** `01.i.k` только внутри `01.i`; паттерн закрыт, когда `ΣK` кусков = `K` паттерна.

## Определение входа по содержимому (до генерации)

Вход — **по содержимому**, не по имени.

### Профили

| `{LAST_STEP_NUMBER}` | Ожидаемый вход | «Свой» | «Чужой» |
|---|---|---|---|
| **`нет` / `00.i`** | Папки (Шаг 0) | есть `Проект`/`Папка`/`Папка ЦИМ`; «Паттерн» пуст | есть `ECM-документ`/`Документ`; «Паттерн» заполнен |
| **`0` / `00`** | Паттерны (Шаг 1) | «Паттерн» заполнен; есть `ECM-документ`/`Документ`; нет папок | папки; «Паттерн» пуст |
| **`01.i[.k]`** | продолжение Шага 1 | «Паттерн» заполнен | документы с пустым «Паттерн» |
| **`01` / `≥ 02`** | Фрагмент Схемы (Шаги 2…N) | документы; «Паттерн» пуст | папки (частично допустимы); «Паттерн» заполнен |

### Алгоритм

```
1. Прочитать файл. Проверить столбцы: Отображаемое имя, Категория, Паттерн.
   Нет → [!] неверная структура → СТОП.
2. Собрать состав: папки N_p, документы N_d, паттерны N_pat, аномалии N_anom.
3. Вывести диагностику ПЕРВЫМ блоком:
   — [!] передан не предпочтительный формат: <имя>   (если .xlsx; первой строкой)
   — Состав входа: папки N_p / документы N_d / паттерны N_pat / аномалии N_anom
   — Профиль по содержимому: <Папки | Паттерны | Документы | неопределён>
4. Валидировать {LAST_STEP_NUMBER} (см. раздел). Пусто/невалидно → СТОП.
5. Сверить профиль с {LAST_STEP_NUMBER}:
   — совпало → продолжить;
   — не совпало → по таблице «Правила несоответствий».
6. Проверить контекст и лимит типов:
   — данных больше, чем помещается в контекст → «[!] Контекст не хватает» → СТОП;
   — ΣK > {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ} → «[!] Контекст превышен: ΣK = <X> > лимита <L>. Уменьшите фрагмент или поднимите лимит.» → СТОП;
   — данных мало, но они невалидны (пустые столбцы) → «[!] Вход неполный: <что пусто>» → СТОП.
```

### Правила несоответствий

| Ситуация | Действие |
|---|---|

| `{LAST_STEP_NUMBER}` = `нет`, есть документы **вперемешку** с папками | предупредить `[!] в таблице папок документы: N_d (отфильтрованы, включая документы с «Паттерн» — в блок не идут)`, продолжить |
| `{LAST_STEP_NUMBER}` = `01`, вход **только документы** | штатно: генерировать `02`, `03`, … |
| `{LAST_STEP_NUMBER}` = `01.i`, вход **только документы** | **СТОП**: `[!] Шаг 1 не завершён (01.i), а вход — документы. Завершите Шаг 1 (01) или проверьте вход.` + `[!] СТОП. Шаг не генерируется.` |

| `{LAST_STEP_NUMBER}` = `00.i`, вход **папки** | **СТОП**: `[!] ожидалось продолжение Шага 0 (папки, подшаг i), вход — папки? Проверьте, что это остаток папок, а не новые паттерны.` — если папки, продолжить как «Таблица папок»; если паттерны — СТОП. |
| `{LAST_STEP_NUMBER}` ≥ `02`, вход **папки** | предупредить `[!] во фрагменте папки: N_p`, продолжить (частично допустимо) |
| «Паттерн» заполнен, категория Папка/Проект/Папка ЦИМ, Шаг 0, K≥2 | в шаг + `[!] папка-паттерн: <имя> (K=<N>)` |
| «Паттерн» заполнен, категория Папка/Проект/Папка ЦИМ, Шаг 0, K=1 | в блок + `[!] папка-паттерн с K=1: <имя>` |
| «Паттерн» заполнен, категория ECM-документ/Документ, Шаг 0 | отфильтровать (как документ), в блок НЕ отправлять |
| «Паттерн» заполнен, Шаги 2…N | в блок (документы — штатный вход) |
| Аномальная категория (`Ярлык`) | `[!] АНОМАЛИЯ категории: <список>` — продолжить |

| Профиль **неопределён** (все классификационные столбцы пусты) | **СТОП**: `[!] Вход неполный: столбцы «Категория»/«Паттерн» пусты. Проверьте, что вход — полный фрагмент, а не только «Отображаемое имя».` |

**Критично (СТОП):** нет столбцов; пустой/невалидный `{LAST_STEP_NUMBER}`; пустой `{INPUT_FILENAME}`; полное несовпадение профиля; профиль неопределён; ΣK > лимита.
**Некритично (продолжить):** аномалии категорий, K=1, документы вперемешку, папки во фрагменте, xlsx, пустые опциональные поля.

1. Проверить обязательные поля. 2. Проверить файл. 3. Собрать состав входа. 4. Валидировать `{LAST_STEP_NUMBER}`. 5. Определить профиль по содержимому. 6. Сверить. 7. Проверить контекст и лимит ΣK. 8. Сгенерировать шаг(и) в формате ниже — **несколько шагов за вызов для профиля «Документы»**, **один шаг (подшаги) для остальных**.

## Формат строки шага (5 колонок, СТРОГО)

```
NN|<тип 1>; <тип 2>; ...|<K>|<Паттерн>|<предупреждение>
```

- `NN` — номер (`00`, `00.i`, `01`, `01.i`, `01.i.k`, `NN` ≥ 2).
- `<типы>` — через `; ` (точка с запятой + пробел).
- `<K>` — количество **уникальных** имён в строке.
- `<Паттерн>` — **только Шаг 1**; в Шагах 0 и 2…N — **пусто**.
- `<предупреждение>` — `[!] …` без символа `|` внутри; пусто, если нет.
  Допустимые: `[!] дубль (N позиций)`, `[!] опечатка: <тип>`, `[!] паттерн разрезан`, `[!] тип в N паттернах`, `[!] папка-паттерн`.

**Пример:**
```
00.1|Объект; 0 Инициация ИСП...|16||
00.2|...|15||
01.1|ТПКР_0 Приказ о старте ПФ ИСП; 1.3.3.2 Приказы...|2|Приказ …|
01.5|Квалификационные аттестаты|1|Квалификационные аттестаты|[!] тип в N паттернах
01.12|ТПКР_1.1 Протокол...; ТПКР _1 Протокол...|3|Протоколы ключевых решений|[!] опечатка: «ТПКР _1» (пробел перед _)
02|...|12||
03|...|13||
```

## Алгоритм генерации

### «Таблица папок» — Шаг 0 (`{LAST_STEP_NUMBER}` = `нет` / `00.i`)
- Вход — Папки. Категории `Проект`/`Папка`/`Папка ЦИМ`; **не включать** `ECM-документ`/`Документ`/`Ярлык`.
- **Папка + «Паттерн», K ≥ 2** → в шаг (это папка) + `[!] папка-паттерн: <имя> (K=<N>)` — информационно, НЕ аномалия.
- **Папка + «Паттерн», K = 1** → в блок «ТРЕБУЮТ РЕШЕНИЯ» + `[!] папка-паттерн с K=1: <имя>`.
- **Документы (любые: с «Паттерн» или без)** → все отфильтровать + `[!] в таблице папок документы: N (отфильтрованы)`. В блок НЕ отправлять.
- Дробление > {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ} — равными частями (ceil(N/2), остаток).
- Формат — 5 колонок, `Паттерн` пуст.
- `00.i` — продолжение: генерировать следующий подшаг `00.(i+1)`, а не начинать заново.

### «Таблица паттернов» — Шаг 1 (`{LAST_STEP_NUMBER}` = `0` / `00` / `01.i[.k]`)
- **Один подшаг = ровно один паттерн. Объединение запрещено.**
- **K = число УНИКАЛЬНЫХ имён в паттерне.**
- **Дубль имени внутри паттерна** (2+ одинаковых «Отображаемое имя») — НЕ K=2, а аномалия:
  **в блок уходят только дублирующиеся строки** с пометкой
  `[!] дубль имени: <имя> (N строк) — разобраться: переименовать или поправить «Входит в»/«Состоит из»`.
  Уникальные строки паттерна остаются в шаге.
- **Один тип в разных паттернах** — `[!] тип в N паттернах: <тип> — разобраться` + в блок.
- **В шаг** идут только паттерны с уникальными именами и K≥2.
- K=1 → блок «ТРЕБУЮТ РЕШЕНИЯ» (`Паттерн|Тип`), не в подшаг.
- Порог дробления на вызовы: P > {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ} **или** ΣK > {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}*10 — по границе паттерна; следующий вызов `{LAST_STEP_NUMBER}` = `01.i`.
- Один гигантский паттерн не влезает — `01.i.1`, `01.i.2`, … `[!] паттерн разрезан: <имя>`.

### «Документы» — Шаги 2…N (`01` / `≥ 02`)
- Вход — фрагмент Схемы.
- **Генерируется НЕСКОЛЬКО шагов за вызов**: от `NN+1` (или `02` при `01`) до лимита `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` ΣK, либо до конца этапа, либо до предела контекста — что наступит раньше. **Не «ровно один шаг».**
- Строки с «Паттерн» → блок.
- Дробление по объёму; целостность уровня; документ/атрибут атомарны.
- Контейнеры — только в Шаге 0.
- Порядок — сверху вниз.
- Номера — `NN+1`, `NN+2`… **точки запрещены** (в Шагах 2…N).

## Блок «ТРЕБУЮТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ»

После шага(ов), до статистики:
```
ТРЕБУЮТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ (в шаг не включены):
<Паттерн>|<Тип>
```
Причины попадания:
- K=1 (одна строка);
- дубль имени внутри паттерна (только дублирующиеся строки);
- тип встречается в нескольких паттернах;
- строка с заполненным «Паттерн» в Шагах 2…N (документы — штатный вход);
- **папка + «Паттерн» с K=1 в Шаге 0** (только эти папки; K≥2 — в шаг, не в блок).

Правила: профиль `нет`/`00.i` — только папка+«Паттерн» K=1; `0`/`00` — K=1 и дубли; `≥02` — любое число «Паттерн». Сортировка по паттерну, затем типу. Точные дубли — `[!] дубль`. Пустые — игнорировать. **В Шаге 0 документы (с «Паттерн» или без) в блок НЕ отправляются — они отфильтровываются.**

## Постобработка (пользователь)

| Ситуация | Действие |
|---|---|
| Тип уже в Шаге 1 | удалить |
| Паттерн есть, типа нет | дописать в `01.i` |
| Паттерна нет, типов несколько | новый подшаг `01.N+1` |
| Паттерна нет, тип один | новый шаг `NN+1` |
| Дубль имени | переименовать или поправить «Входит в»/«Состоит из» |

```
Проверка лимита: ΣK <L> → <ОК | ПРЕВЫШЕН (СТОП)>
```

## Правила вывода (СТРОГО)
- Для профиля «Документы» — **несколько шагов за вызов**; для остальных — один шаг (подшаги).
- Без markdown-разметки внутри списка.
- **Запрещено**: паттерны/справочники (выход №0.2), `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}`, `{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}`, полный список шагов.
- Вход — не по имени файла.
- Символ `|` внутри предупреждения — **запрещён**.

## Самопроверка перед отправкой
- Обязательные поля заполнены: `{LAST_STEP_NUMBER}` (не пусто, `нет` допустимо), `{INPUT_FILENAME}` (не пусто).
- Опциональные пустые — считать «нет»/50, не СТОП.
- Профиль вызова определён: `нет`/`00.i` → папки; `0`/`00`/`01.i[.k]` → паттерны; `01`/`≥02` → документы.
- `00.i` трактуется как «Таблица папок», а НЕ «Таблица паттернов».
- `0` = `00` (явно).
- `01` (без точки) — ВСЕГДА «Шаг 1 завершён» → Шаг 2; не `01.i`.
- `01.i` — СТОП, если вход документы («Шаг 1 не завершён»).
- Для профиля «Документы» сгенерировано НЕСКОЛЬКО шагов (не «ровно один»).
- ΣK ≤ `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}`; при превышении — СТОП с сообщением «Контекст превышен».
- Каждая строка — **5 колонок**; `|` внутри предупреждения нет.
- `Паттерн` заполнен только в Шаге 1.
- Шаг 1: подшаг = ровно один паттерн (объединение запрещено).
- Шаг 1: K = уникальные имена; дубли имени → в блок только дублирующиеся строки.
- Шаги 2…N: номера последовательные, без точек.
- ΣK = числу типов в статистике (при СТОП — «не применимо»).
- Баланс строк включает «отфильтровано»: вход = шаг + блок + отфильтровано.
- Баланс паттернов (Шаг 1): P = подшагов + в блоке.
- При разрезанном паттерне: ΣK кусков = K паттерна.
- Шаг 0: документы (любые) — отфильтрованы, в блок не идут; папка + «Паттерн» K≥2 — в шаге с пометкой; K=1 — в блоке.
- Шаги 2…N: строки с «Паттерн» — только в блоке.
- При нехватке контекста — СТОП; различать «Контекст не хватает» / «Контекст превышен (ΣK)» / «Вход неполный».
- Есть статистика.

## Как пользователь сохранит результат
1. Шаг(и) — в `04_Промты\Шаги\Шаг_<NN>.md` (UTF-8, без BOM).
2. Блок «ТРЕБУЮТ РЕШЕНИЯ» — в сводный `Требуют_решения.md`.
3. Статистика — справочно.
4. Постобработка блока — по таблице.
5. Склейка — по 5 колонкам, программно/вручную.
6. Дробление Шага 1: следующий вызов `{LAST_STEP_NUMBER}` = `01.i`; когда все паттерны покрыты — `01`.
7. Профиль «Документы»: каждый следующий вызов — с `{LAST_STEP_NUMBER}` = последний сгенерированный NN; генерируется несколько шагов до предела.
