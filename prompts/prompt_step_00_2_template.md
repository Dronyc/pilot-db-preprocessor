# Промт №0.2: Извлечение и систематизация паттернов

## Задача
Проанализируй предоставленные данные и извлеки паттерны согласно структуре листа «Паттерны» (секции A-D и H-O).

## Инструкции по извлечению паттернов

### Шаг 1: Анализ структуры данных
Изучи предоставленные данные и определи:
- Какие секции листа «Паттерны» применимы к текущим данным
- Какие паттерны уже известны и должны быть учтены
- Какие исключения необходимо соблюдать

### Шаг 2: Систематизация по секциям

#### Секция A: Основные идентификаторы
- Извлеки уникальные идентификаторы объектов
- Определи формат и структуру идентификаторов
- Зафиксируй правила именования

#### Секция B: Атрибуты и свойства
- Выдели ключевые атрибуты объектов
- Определи типы данных для каждого атрибута
- Зафиксируй обязательные и опциональные поля

#### Секция C: Связи и зависимости
- Определи связи между объектами
- Зафиксируй иерархические отношения
- Выдели родительские и дочерние элементы

#### Секция D: Правила валидации
- Извлеки правила проверки данных
- Определи ограничения и границы значений
- Зафиксируй условия корректности

#### Секция H: Паттерны именования
- Выдели регулярные выражения для имён
- Определи шаблоны суффиксов и префиксов
- Зафиксируй правила трансформации имён

#### Секция I: Паттерны путей
- Извлеки шаблоны файловых путей
- Определи структуру директорий
- Зафиксируй правила организации файлов

#### Секция J: Паттерны метаданных
- Выдели структуры метаданных
- Определи форматы описания
- Зафиксируй обязательные поля метаданных

#### Секция K: Паттерны контента
- Извлеки шаблоны содержимого файлов
- Определи структуру данных внутри файлов
- Зафиксируй правила форматирования

#### Секция L: Паттерны версионирования
- Выдели правила управления версиями
- Определи форматы версий
- Зафиксируй правила нумерации

#### Секция M: Паттерны категоризации
- Извлеки системы классификации
- Определи иерархию категорий
- Зафиксируй правила отнесения к категориям

#### Секция N: Паттерны статусов
- Выдели возможные состояния объектов
- Определи правила переходов между статусами
- Зафиксируй условия изменения статуса

#### Секция O: Паттерны исключений
- Извлеки специальные случаи обработки
- Определи условия применения исключений
- Зафиксируй правила обхода стандартных паттернов

### Шаг 3: Проверка на исключения
Для каждого извлечённого паттерна проверь:
- Не попадает ли он в список исключений ({{ИСКЛЮЧЕНИЯ_ПАТТЕРНОВ}})
- Не противоречит ли известным паттернам ({{СПИСОК_ИЗВЕСТНЫХ_ПАТТЕРНОВ}})
- Соответствует ли правилам матчинга (см. ниже)

Если паттерн попадает в исключения — исключи его из результата.
Если паттерн противоречит известному — отметь как «требует уточнения».

### Шаг 4: Форматирование результата
Представь результат в виде структурированного списка:

```
СЕКЦИЯ [Буква]: [Название секции]
- Паттерн 1: [описание]
  * Формат: [формат паттерна]
  * Пример: [пример применения]
  * Исключения: [если есть]

- Паттерн 2: [описание]
  * Формат: [формат паттерна]
  * Пример: [пример применения]
  * Исключения: [если есть]
```

## Правила матчинга
1. Паттерн считается применённым, если данные соответствуют формату с точностью до 95%
2. При конфликте паттернов приоритет имеет более специфичный паттерн (Тип > Категория)
3. При равной конкретности — СТОП (запрос уточнения у пользователя)
4. Исключения всегда имеют приоритет над стандартными паттернами
5. Если паттерн не может быть однозначно определён, отметь его как «требует уточнения»

## Критерии завершения
- Все применимые секции (A-D, H-O) проанализированы
- Извлечённые паттерны проверены на исключения
- Результат отформатирован согласно требованиям
- Нет противоречий с известными паттернами
- Все конфликты разрешены или помечены для уточнения
