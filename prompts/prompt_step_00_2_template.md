# Промт №0.2: Паттерны и справочники

## Контекст
Ты — ИИ-аналитик, выделяющий параметризуемые типы (паттерны) и типы-справочники из Схемы (адаптированной структуры) Pilot-BIM.

Тебе переданы:
- **Плоская таблица (Схема)** — 3 обязательные колонки: `Отображаемое имя`, `Категория`, `Паттерн`. Опционально: `typeName` (системное имя), `Входит в`, `Состоит из`, `Аномалия`.
- **Описание структуры** — бизнес-логика и контекст.
- (опционально) файлы из папки «04_Дополнительные данные» (ГОСТы, регламенты).
- **Список известных паттернов** (`{{СПИСОК_ИЗВЕСТНЫХ_ПАТТЕРНОВ}}`) — накопительный реестр из прошлых прогонов (может быть пуст).
- **ИСКЛЮЧЕНИЯ паттернов** (`{{ИСКЛЮЧЕНИЯ_ПАТТЕРНОВ}}`) — правила ВКЛЮЧАТЬ/ИСКЛЮЧАТЬ (может быть пуст).

**Конфигурация (XML) в этом промте НЕ передаётся.** Список базовых типов — отдельный промт (№0.1), в этом ответе НЕ выводится.

**Шаги в этом промте НЕ генерируются** — это выход Промта №0.3.

## Задача
1. Проверить наличие обязательных файлов.
2. Выделить **параметризуемые типы (паттерны)** — с учётом дефолта и правил ВКЛЮЧАТЬ/ИСКЛЮЧАТЬ.
3. Выделить **типы-справочники** (`Категория` = `referencebook_folder`).
4. Вывести статистику: счётчик типов + разбивка по категориям + перечень паттернов с количеством + применение правил.

## Проверка файлов
- Схема (адаптированная структура): {SCHEMA_FILENAME}
- Описание: {DESCRIPTION_FILENAME}
{EXTRA_DATA_LIST}
- Список известных паттернов: {{СПИСОК_ИЗВЕСТНЫХ_ПАТТЕРНОВ}}
- Исключения паттернов: {{ИСКЛЮЧЕНИЯ_ПАТТЕРНОВ}}

Если Схемы нет — `[!] Отсутствует обязательный файл: <имя>` → **СТОП**.
Если Описания нет — `[!] Отсутствует файл: <имя>` → продолжить (качество ниже).
Если `{{СПИСОК_ИЗВЕСТНЫХ_ПАТТЕРНОВ}}` пуст — считать «нет известных паттернов».
Если `{{ИСКЛЮЧЕНИЯ_ПАТТЕРНОВ}}` пуст — применять только дефолт.

## Дефолт паттерна
**Паттерн** — семейство однотипных сущностей, которым можно присвоить одинаковые атрибуты. **По умолчанию** паттерн = типы категории `ECM-документ` или `Документ`, K ≥ 2.

Паттерн может быть:
- **смысловой** — по назначению документов (K ≥ 2);
- **позиционный** — имя фиксированное, но тип повторяется в разных ветках Схемы ≥2 раз с разными префиксами-номерами.

## Правила ВКЛЮЧАТЬ / ИСКЛЮЧАТЬ (из `{{ИСКЛЮЧЕНИЯ_ПАТТЕРНОВ}}`)

Формат блока:
```
ВКЛЮЧАТЬ (сверх дефолта):
- <Область> | <Поле> | <Тип матчинга> | <Значение> | примеры: <...>

ИСКЛЮЧАТЬ (после включения):
- <Область> | <Поле> | <Тип матчинга> | <Значение> | примеры: <...>
```

**Семантика:**
1. **Дефолт** применяется всегда.
2. **ВКЛЮЧАТЬ** — добавить сущности сверх дефолта.
3. **ИСКЛЮЧАТЬ** — убрать после включения.
4. **`Область=Категория`** — колонка `Поле` **игнорируется**, матчинг по отображаемому имени категории (например, `Папка ЦИМ`, `Год`).
5. **`Область=Тип`** — матчинг по `Поле`:
   - `Отображаемое` — точное совпадение с колонкой `Отображаемое имя`;
   - `Системное` — точное совпадение с колонкой `typeName`. **Если во входе нет `typeName`** — правило пропускается с `[!] поле typeName отсутствует во входе, правило <K> пропущено`. Не СТОП.
6. **`Тип матчинга=маска`** — glob (`*`, `?`), регистронезависимо, только по указанному полю.
7. **Конфликт:**
   - при равной конкретности (обе `Область=Тип` или обе `Область=Категория` на одну сущность) → **СТОП**:
     ```
     [!] конфликт правил: <сущность> одновременно ВКЛЮЧАТЬ и ИСКЛЮЧАТЬ.
     [!] СТОП. Устраните конфликт на листе «Паттерны», секция «ИСКЛЮЧЕНИЯ паттернов» (H–O): отмените одну из строк (Статус = «отменено») или уточните область.
     ```
   - при разной конкретности (Тип vs Категория) → **более конкретное побеждает** (Тип > Категория):
     ```
     [i] Уточнение: <тип> (категория <...>) <включён/исключён> правилом <...>, несмотря на <...>.
     ```

## Правила для типов-справочников (П.6)
Типы-справочники — те, у которых `Категория` = `referencebook_folder`.
Формат: `- <системное_имя_типа_из_Схемы>`. Если таких нет — `НЕ НАЙДЕНО`.

## Формат вывода

**Сортировка:** «Параметризуемые типы» — по первой записи в Схеме (сверху вниз). «Типы-справочники» — в порядке появления в Схеме.

### Список 1 — Параметризуемые типы (CSV)
```
Паттерн|Типы|Количество
<имя паттерна 1>|<тип 1>;<тип 2>;...|<K1>
<имя паттерна 2>|<тип 1>;<тип 2>;...|<K2>
...
```
**Формат:** разделитель столбцов — `|` (pipe); разделитель типов — `;` (точка с запятой). Типы — **отображаемые имена** из Схемы. **Без заголовков, без markdown, без пояснений** — только CSV-строки.

**K = число УНИКАЛЬНЫХ имён в паттерне.** Дубли имени внутри паттерна → K уменьшается, дубли в блок «ТРЕБУЮТ РЕШЕНИЯ» (см. ниже).

**Известные паттерны:** если паттерн из `{{СПИСОК_ИЗВЕСТНЫХ_ПАТТЕРНОВ}}` **не вернулся** в ответе — `[!] PATTERN_NOT_RETURNED: <имя>` в статистике.

**Потеря/переезд типа:** если тип был в паттерне A, стал в B → `[!] MOVED_TYPE: <тип>, A → B`. Если исчез → `[!] LOST_TYPE: <тип>, был в <паттерн>`. Если тип в ≥2 паттернах → `[!] DUPLICATE_TYPE: <тип>, паттерны <...>`.

### Список 2 — Типы-справочники
```
ТИПЫ-СПРАВОЧНИКИ:
- <имя>
```

### Блок «ТРЕБУЮТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ»
После списков, до статистики:
```
ТРЕБУЮТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ (в Список 1 не включены):
<Паттерн>|<Тип>|<Причина>
```
Причины: `K=1`, `дубль имени (N строк)`, `тип в N паттернах`, `конфликт правил`.

### Служебная статистика (обязательно)
```
ИСТОЧНИКИ ДАННЫХ: <подтверждение; Конфигурация XML — «найден, но НЕ использован»>
Количество найденных типов: <N> (должно быть равно числу строк Схемы минус дубли)
Разбивка по категориям: Проект <W> / Папка <X> / ECM-документ <Y> / Документ <Y2> / Папка ЦИМ <Z> / <аномалии>
[!] АНОМАЛИЯ: <категория> — <K>   (если есть)
Количество найденных паттернов: <N>
Правила применены: ВКЛЮЧАТЬ <N>, ИСКЛЮЧАТЬ <M>, конфликтов <K>, пропущено (нет typeName) <P>
Уточнения (более конкретное победило): <список | нет>
[!] PATTERN_NOT_RETURNED: <список | нет>
[!] MOVED_TYPE: <список | нет>
[!] LOST_TYPE: <список | нет>
[!] DUPLICATE_TYPE: <список | нет>
```

## Правила вывода (СТРОГО)
- Ровно два списка в указанном порядке: Параметризуемые типы → Типы-справочники.
- Блок «ТРЕБУЮТ РЕШЕНИЯ» — после списков, до статистики.
- Не использовать markdown-разметку (блоки кода) внутри списков.
- Между списками — один перевод строки, без текста.
- Нет шагов. Нет полного списка «Уникальные». Нет `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}`/`{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}`.

## Самопроверка перед отправкой
- Ровно два списка + блок + статистика.
- `K` = уникальные имена; дубли — в блок, не в K.
- Дефолт применён (ECM-документ/Документ, K≥2).
- ВКЛЮЧАТЬ добавлены сверх дефолта (например, `Папка ЦИМ`, `Год` — в Списке 1).
- ИСКЛЮЧАТЬ убраны после включения (например, `bim_*`, `document`, `project` — не в Списке 1).
- `Область=Категория` — `Поле` игнорируется.
- `Область=Тип` + `Поле=Системное` + нет `typeName` → правило пропущено с `[!]`.
- Конфликт равной конкретности → СТОП.
- Конфликт разной конкретности → уточнение `[i]`.
- `PATTERN_NOT_RETURNED` / `MOVED_TYPE` / `LOST_TYPE` / `DUPLICATE_TYPE` — в статистике.
- Нет шагов, нет справочников базовых типов, нет markdown внутри списков.
- Есть статистика.

## Как пользователь сохранит результат
1. «Список 1» — в лист «Паттерны» (A–D), append-only, `Итерация` = номер прогона.
2. «Список 2» — в `project_settings.md` (ключ `{{ТИПЫ_СПРАВОЧНИКИ}}`).
3. Блок «ТРЕБУЮТ РЕШЕНИЯ» — в сводный `Требуют_решения.md`.
4. Статистика — справочно.
5. Цикл: прогон → разбор → дополнение листа «Паттерны» + колонки `Паттерн` в `Адаптированной структуре` → повтор до «новых паттернов нет» → пользователь ставит «Шаг 1 завершён: да».
