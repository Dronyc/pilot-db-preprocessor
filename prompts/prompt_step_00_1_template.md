# Промт №0.1: Базовые типы из Конфигурации

## Контекст
Ты — ИИ-аналитик, извлекающий базовые типы из XML-файла Конфигурации
Pilot-BIM. Твоя задача — сформировать фрагмент `project_settings.md` с
ключом `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}`.

**Схема и Описание в этом промте НЕ передаются.** Они использовались в
Промте №0 (декомпозиция). Здесь вход — только Конфигурация.

## Проверка файлов
- Конфигурация: {CONFIG_FILENAME}

Если файла нет — выведи сообщение
`[!] Отсутствует обязательный файл: Конфигурация` и остановись.
Если Конфигурация не читается — выведи
`НЕ СФОРМИРОВАН: конфигурация не читается` и НЕ выдумывай типы.

## Правила для списка базовых типов (П.5)

Выпиши базовые типы из файла Конфигурации по правилу:

1. **Корневые типы (включай всегда):**
   - `referencebook_folder` (Папка справочников)
   - `projectfolder` (Папка проектов)

2. **Дочерние типы:** включай ВСЕ дочерние типы ЛЮБОГО уровня для:
   - `referencebook_folder` (пример: `item_reference_sections`,
     `item_reference_sets`, `item_reference_subsection` — дочерние,
     включай);
   - `projectfolder` (пример: `project` — дочерний; `building`,
     `section`, `main_set` — дочерние `project`, т.е. второго уровня;
     включай всех).

3. **Отдельные типы (включай САМ тип, но НЕ его дочерние):**
   - `bim_coordinationModel` (Консолидированная BIM-модель);
   - `doc_remarksFolder` (Папка замечаний к документу).

   ВАЖНО: дочерние этих типов в список НЕ включай, даже если они есть
   в Конфигурации. Пример: `bim_modelPartFolder` — дочерний
   `bim_coordinationModel`, в список базовых типов НЕ входит.

4. **Типы, которые НЕ включай (ни сам тип, ни его дочерние):**
   - `photo360Album` (Альбом Фото 360) — и все его дочерние.

**Формат вывода — строки в виде:**

    {{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <системное_имя_типа>

По одной строке на тип. Только типы, реально найденные в Конфигурации.
Если тип из списка отсутствует в Конфигурации — пропусти его
(не выдумывай).

## Формат вывода

Подготовь **один список** в формате, готовом для вставки в `.md`:

    {{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <системное_имя_типа>
    {{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <системное_имя_типа>
    ...

### Правила вывода (СТРОГО)
- Ровно один список.
- Только строки `{{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <имя>`.
- **НЕ включай:** заголовки, комментарии, `{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}`,
  списки уникальных/параметризуемых типов, списки справочников,
  `Шаги.txt`.
- Не используй markdown-разметку (блоки кода) внутри списка.
- Не используй маркеры `<<<...>>>`, `===...===` и подобные.

### Самопроверка перед отправкой
- Ровно один список.
- Все строки начинаются с `{{СПИСОК_БАЗОВЫХ_ТИПОВ}} = `.
- `photo360Album` отсутствует (и его дочерние).
- `bim_coordinationModel` и `doc_remarksFolder` присутствуют сами,
  без дочерних (если они есть в Конфигурации).
- Нет markdown-разметки внутри списка.

## Как пользователь сохранит результат
Скопировать список в `04_Промты\Шаблоны\project_settings.md` — заменить
(или дополнить) ключ `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}`. Ключ
`{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}` заполняется отдельно по образцу
`prompts/project_settings.md.example`.
