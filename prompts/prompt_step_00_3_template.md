# Промт №0.3: Список шагов (ступени «Таблица папок» / «Таблица паттернов» / «Документы»)

## ВНИМАНИЕ ПЕРЕД ЧТЕНИЕМ
`01` (без точки) — это НЕ `01.i`. `01` = «Шаг 1 завершён → генерируй Шаг 2». `01.i` (с точкой) = «продолжай Шаг 1, подшаг i». Не путать.

## ВХОДНЫЕ ПАРАМЕТРЫ (заполнить перед вызовом)

| Параметр | Обязательность | Значение | Допустимые формы |
|---|---|---|---|
| **Шаг** | **обязательно** | `{LAST_STEP_NUMBER}` | `нет` (Шаг 0), 0, 00, 00.i, 01, 01.i, 01.i.k, NN (≥2). **Пусто — недопустимо.** |
| **Имя входного файла** | **обязательно** | `{INPUT_FILENAME}` | **Пусто — недопустимо.** |
| **Описание** | опционально | `{DESCRIPTION_FILENAME}` | имя или «нет»; пусто = «нет» |
| **Дополнительные данные** | опционально | `{EXTRA_DATA_LIST}` | список или «нет»; пусто = «нет» |
| **Лимит типов в таблице** | опционально | `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` | целое число; пусто = 50 |

> Обязательные: параметр «Шаг», параметр «Имя входного файла».
> Для Шага 0 укажите значение параметра «Шаг» = `нет` (не пусто!).
> Пустое значение в обязательном параметре → СТОП с требованием заполнить.
> Опциональные — пусто = «нет», на работу не влияют.

## Контекст
Ты — ИИ-архитектор, планирующий пошаговую декомпозицию задачи генерации настроек БД Pilot-BIM.

Профиль вызова определяется значением параметра «Шаг» (`{LAST_STEP_NUMBER}`):
- **«Таблица папок»** (`нет`, `00.i`) — генерируешь Шаг 0 (или продолжение).
- **«Таблица паттернов»** (`0`, `00`, `01.i`, `01.i.k`) — генерируешь Шаг 1 (или продолжение).
- **«Документы»** (`01`, `≥02`) — генерируешь **несколько шагов за вызов** (Шаг 2, 3, … до конца этапа/предела).

Тебе передан **один входной файл**:
- **Таблица всех Папок** (ступень «Таблица папок»): все папки.
- **Таблица всех Паттернов** (ступень «Таблица паттернов»): паттерны + типы.
- **Фрагмент Схемы** (ступень «Документы», Шаги 2…N): часть Схемы.

Также: Описание, (опц.) доп. данные.

**Конфигурация (XML) НЕ передаётся.**

**Правило непрерывной разбивки (Continuous Breakdown):**
Твоя задача — максимально эффективно использовать предоставленный контекст. 
1. Если ты завершил генерацию подшагов для текущего профиля (например, полностью разбил Шаг 0 на подшаги `00.1`, `00.2`...) и в окне контекста **остаётся свободное место**, **НЕ ОСТАНАВЛИВАЙСЯ**.
2. Автоматически переходи к разбивке следующего логического шага. Например, после Шага 0 (`нет`/`00.i`) переходи к Шагу 1 (`0`/`00`/`01.i`), генерируя для него подшаги. После завершения Шага 1 переходи к Шагу 2 и так далее.
3. Продолжай генерировать подшаги для последовательных шагов, формируя при необходимости **несколько независимых CSV-блоков** (каждый из которых строго не превышает `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` типов/строк), пока не закончится свободное место в контексте или не будут обработаны все доступные типы.
4. Для каждого нового шага в цепочке строго соблюдай правила валидации параметра «Шаг» и профиль входа, как если бы это был отдельный вызов.

## Проверка файлов

- **Входной файл**: {INPUT_FILENAME}
- **Номер последнего шага**: см. значение параметра «Шаг» в «ВХОДНЫЕ ПАРАМЕТРЫ»
- Описание: {DESCRIPTION_FILENAME}
{EXTRA_DATA_LIST}
- **Лимит типов в таблице**: {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}

**Проверка обязательных полей (до всего):**
- Значение параметра «Шаг» отсутствует → `[!] Параметр «Шаг» не заполнен. Укажите номер предыдущего шага или «нет» для Шага 0.` → **СТОП**.
- Значение параметра «Имя входного файла» отсутствует → `[!] Параметр «Имя входного файла» не заполнен. Укажите имя входного файла.` → **СТОП**.
- Нет входного файла → `[!] Отсутствует обязательный файл: <имя>` → **СТОП**.
- Нет Описания → `[!] Отсутствует файл: <имя>` → продолжить (качество ниже).
- Значения параметров «Описание» / «Дополнительные данные» отсутствуют → считать «нет», продолжить.
- Значение параметра «Лимит типов в таблице» отсутствует → считать 50, продолжить.

## Валидация параметра «Шаг» (СТРОГО, до всего)

Допустимые формы: **`нет`**, `0`, `00`, `00.i`, `01`, `01.i`, `01.i.k`, `NN` (NN ≥ 2). **Пусто — недопустимо.**

| Значение | Профиль | Что генерировать |
|---|---|---|
| **`нет`** | «Таблица папок» | Шаг 0 |
| **`00.i`** | «Таблица папок» | Продолжение Шага 0 (подшаг `i+1`) |
| **`0` / `00`** | «Таблица паттернов» | Шаг 1 с `01.1` |
| **`01.i`** | «Таблица паттернов» | `01.(i+1)`… |
| **`01.i.k`** | «Таблица паттернов» | `01.i.(k+1)`… затем `01.(i+1)` |
| **`01`** | «Документы» | **Шаг 1 завершён** → Шаги `02`, `03`, … до лимита/конца этапа/предела |
| **`≥ 02`** | «Документы» | Продолжение: Шаг NN+1, NN+2, … до предела |

**Пустое значение параметра «Шаг»** →
```
[!] Параметр «Шаг» не заполнен. Укажите номер предыдущего шага или «нет» для Шага 0.
[!] СТОП. Шаг не генерируется.
```
→ **СТОП**.

**Невалидное значение параметра «Шаг»** (например, литерал `{LAST_STEP_NUMBER}`, `01.15.2.1`, буквы) →
```
[!] Неверный формат параметра «Шаг»: <значение>
[!] СТОП. Шаг не генерируется. Допустимые формы: нет, 0, 00, 00.i, 01, 01.i, 01.i.k, NN (≥2).
```
→ **СТОП**. Не подставлять «нет», не автокорректировать.

**Критично:**
- `01` — ВСЕГДА «Шаг 1 завершён» → Шаг 2. НЕ трактовать как `01.i`.
- Правило «Шаг 1 не завершён» (СТОП) — ТОЛЬКО для `01.i` (с точкой).
- `00.i` — это «Таблица папок», а НЕ «Таблица паттернов».

**Разрезанный паттерн:** `01.i.k` только внутри `01.i`; паттерн закрыт, когда `ΣK` кусков = `K` паттерна.

## Определение входа по содержимому (до генерации)

Вход — **по содержимому**, не по имени.

### Профили

| Значение параметра «Шаг» | Ожидаемый вход | «Свой» | «Чужой» |
|---|---|---|---|
| **`нет` / `00.i`** | Папки (Шаг 0) | есть `Проект`/`Папка`/`Папка ЦИМ`; «Паттерн» пуст | есть `ECM-документ`/`Документ`; «Паттерн» заполнен |
| **`0` / `00`** | Паттерны (Шаг 1) | «Паттерн» заполнен; есть `ECM-документ`/`Документ`; нет папок | папки; «Паттерн» пуст |
| **`01.i[.k]`** | продолжение Шага 1 | «Паттерн» заполнен | документы с пустым «Паттерн» |
| **`01` / `≥ 02`** | Фрагмент Схемы (Шаги 2…N) | документы; «Паттерн» пуст | папки (частично допустимы); «Паттерн» заполнен |

### Алгоритм

```
1. Прочитать файл. Проверить столбцы: Отображаемое имя, Категория, Паттерн.
   Нет → [!] неверная структура → СТОП.
2. Собрать состав: папки N_p, документы N_d, паттерны N_pat, аномалии N_anom.
3. Вывести диагностику ПЕРВЫМ блоком:
   — [!] передан не предпочтительный формат: <имя>   (если .xlsx; первой строкой)
   — Состав входа: папки N_p / документы N_d / паттерны N_pat / аномалии N_anom
   — Профиль по содержимому: <Папки | Паттерны | Документы | неопределён>
4. Валидировать значение параметра «Шаг» (см. раздел). Пустое/невалидное → СТОП.
5. Сверить профиль со значением параметра «Шаг»:
   — совпало → продолжить;
   — не совпало → по таблице «Правила несоответствий».
6. Проверить контекст и лимит типов:
   — данных больше, чем помещается в контекст → «[!] Контекст не хватает» → СТОП;
   — ΣK > {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ} → «[!] Контекст превышен: ΣK = <X> > лимита <L>. Уменьшите фрагмент или поднимите лимит.» → СТОП;
   — данных мало, но они невалидны (пустые столбцы) → «[!] Вход неполный: <что пусто>» → СТОП.
```

### Правила несоответствий

| Ситуация | Действие |
|---|---|
| Значение параметра «Шаг» = `нет`, вход **только документы** (N_p=0, N_d>0, N_pat=0) | **СТОП**: `[!] несоответствие: ожидался Шаг 0 (папки), вход — только документы.` + `[!] Похоже на Шаги 2…N. Если намеренно — повторите со значением параметра «Шаг» = 01.` + `[!] СТОП. Шаг не генерируется.` |
| Значение параметра «Шаг» = `нет`, есть документы **вперемешку** с папками | предупредить `[!] в таблице папок документы: N_d (отфильтрованы, включая документы с «Паттерн» — в блок не идут)`, продолжить |
| Значение параметра «Шаг» = `01`, вход **только документы** | штатно: генерировать `02`, `03`, … |
| Значение параметра «Шаг» = `01.i`, вход **только документы** | **СТОП**: `[!] Шаг 1 не завершён (01.i), а вход — документы. Завершите Шаг 1 (01) или проверьте вход.` + `[!] СТОП. Шаг не генерируется.` |
| Значение параметра «Шаг» = `0`/`00`, вход **папки** | **СТОП**: `[!] ожидался Шаг 1 (паттерны), вход — папки. Похоже на Шаг 0.` |
| Значение параметра «Шаг» = `00.i`, вход **папки** | **СТОП**: `[!] ожидалось продолжение Шага 0 (папки, подшаг i), вход — папки? Проверьте, что это остаток папок, а не новые паттерны.` — если папки, продолжить как «Таблица папок»; если паттерны — СТОП. |
| Значение параметра «Шаг» ≥ `02`, вход **папки** | предупредить `[!] во фрагменте папки: N_p`, продолжить (частично допустимо) |
| «Паттерн» заполнен, категория Папка/Проект/Папка ЦИМ, Шаг 0, K≥2 | в шаг + `[!] папка-паттерн: <имя> (K=<N>)` |
| «Паттерн» заполнен, категория Папка/Проект/Папка ЦИМ, Шаг 0, K=1 | в шаг + `[!] папка-паттерн с K=1: <имя>` (информационно, НЕ аномалия) |
| «Паттерн» заполнен, категория ECM-документ/Документ, Шаг 0 | отфильтровать (как документ), в блок НЕ отправлять |
| «Паттерн» заполнен, Шаги 2…N | в блок (документы — штатный вход) |
| Аномальная категория (`Ярлык`) | `[!] АНОМАЛИЯ категории: <список>` — продолжить |
| Паттерн с K=1 (профиль «Таблица паттернов») | в шаг как отдельный подшаг `01.i` |
| xlsx вместо CSV | `[!] передан не предпочтительный формат: <имя>` — продолжить |
| Профиль **неопределён** (все классификационные столбцы пусты) | **СТОП**: `[!] Вход неполный: столбцы «Категория»/«Паттерн» пусты. Проверьте, что вход — полный фрагмент, а не только «Отображаемое имя».` |

**Критично (СТОП):** нет столбцов; пустое/невалидное значение параметра «Шаг»; пустое значение параметра «Имя входного файла»; полное несовпадение профиля; профиль неопределён; ΣK > лимита.
**Некритично (продолжить):** аномалии категорий, документы вперемешку, папки во фрагменте, xlsx, пустые опциональные поля.

## Формат строки шага (5 колонок, СТРОГО)

**ВАЖНО: Правило разбивки на блоки.** 
Ты должен распределить ВСЕ предоставленные типы. Однако каждый генерируемый CSV-блок не должен содержать более `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` типов. 
Если общее количество типов превышает лимит, ты обязан сгенерировать **несколько независимых блоков**, каждый из которых обрамлён маркерами:
<!-- STEPS_CSV_START -->
(CSV-данные, не более {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ} строк)
<!-- STEPS_CSV_END -->
Повторяй эту структуру столько раз, сколько необходимо для покрытия всех типов.

Ты обязан обрамить список строк шагов жесткими маркерами на отдельных строках. Никакого текста или markdown-разметки внутри маркеров. Заголовочной строки внутри маркеров нет — только строки шагов.
При СТОП список шагов не генерируется и маркеры НЕ выводятся.

<!-- STEPS_CSV_START -->
NN|<тип 1>; <тип 2>; ...|<K>|<Паттерн>|<предупреждение>
<!-- STEPS_CSV_END -->

- `NN` — номер (`00`, `00.i`, `01`, `01.i`, `01.i.k`, `NN` ≥ 2).
- `<типы>` — через `; ` (точка с запятой + пробел).
- `<K>` — число **РАЗЛИЧНЫХ** уникальных имён типов. Типы с одинаковым «Отображаемым именем», но принадлежащие разным родителям, считаются **разными** типами и увеличивают K. Дедупликация (счёт как одно имя) применяется только к полным дубликатам (одинаковое имя и родитель).
- `<Паттерн>` — **только Шаг 1**; в Шагах 0 и 2…N — **пусто**.
- `<предупреждение>` — `[!] …` без символа `|` внутри; пусто, если нет.
  Допустимые: `[!] дубль (N позиций)`, `[!] опечатка: <тип>`, `[!] паттерн разрезан`, `[!] тип в N паттернах`, `[!] папка-паттерн`.

**Пример:**
<!-- STEPS_CSV_START -->
00.1|Объект; 0 Инициация ИСП; 1.1 Договоры|16||
00.2|2.1 Акты; 2.2 Протоколы; 3.1 Приказы|15||
01.1|ТПКР_0 Приказ о старте ПФ ИСП; 1.3.3.2 Приказы...|2|Приказ …|
01.5|Квалификационные аттестаты|1|Квалификационные аттестаты|[!] тип в N паттернах
01.12|ТПКР_1.1 Протокол...; ТПКР _1 Протокол...|3|Протоколы ключевых решений|[!] опечатка: «ТПКР _1» (пробел перед _)
02|...|12||
03|...|13||
<!-- STEPS_CSV_END -->

## Алгоритм генерации

### «Таблица папок» — Шаг 0 (значение параметра «Шаг» = `нет` / `00.i`)
- **ВАЖНО для Шага 0:** При разбивке на подшаги обязательно учитывай колонку «Паттерн». Если папке (категория «Папка», «Проект» или «Папка ЦИМ») присвоен паттерн (колонка «Паттерн» не пуста), такая папка является **папкой-паттерном**. Она должна обрабатываться как единая сущность: не разбивай её внутреннюю структуру на отдельные подшаги, если это не требуется явно; группируй такие папки согласно их паттерну.
- Вход — Папки. Категории `Проект`/`Папка`/`Папка ЦИМ`; **не включать** `ECM-документ`/`Документ`/`Ярлык`.
- **Папка + «Паттерн», K ≥ 2** → в шаг (это папка) + `[!] папка-паттерн: <имя> (K=<N>)` — информационно, НЕ аномалия.
- **Папка + «Паттерн», K = 1** → в шаг + `[!] папка-паттерн с K=1: <имя>` (информационно, НЕ аномалия).
- **Документы (любые: с «Паттерн» или без)** → все отфильтровать + `[!] в таблице папок документы: N (отфильтрованы)`. В блок НЕ отправлять.
- **Правило целостности паттерна при распределении по шагам:**
  1. Все типы, принадлежащие одному паттерну (одинаковое значение в колонке «Паттерн» входного CSV), **обязаны** попасть в один и тот же шаг. Запрещено размазывать типы одного паттерна по разным шагам.
  2. В один шаг **разрешено** включать типы из нескольких разных паттернов, если суммарное количество типов не превышает `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` и они логически связаны (например, относятся к одной категории или фазе проекта).
  3. Если добавление следующего паттерна в текущий шаг превысило бы лимит, **закрой текущий шаг** и начни новый — даже если в нём будет только один паттерн. Не разрезай паттерн.
  4. Приоритет заполнения: сначала заполняй шаг до лимита, добавляя паттерны целиком; не начинай новый шаг, пока в текущий помещается хотя бы один целый паттерн.
- Формат — 5 колонок, `Паттерн` пуст.
- `00.i` — продолжение: генерировать следующий подшаг `00.(i+1)`, а не начинать заново.

### «Таблица паттернов» — Шаг 1 (значение параметра «Шаг» = `0` / `00` / `01.i[.k]`)
- **Один подшаг = ровно один паттерн. Объединение запрещено.**
- **K = число УНИКАЛЬНЫХ имён в паттерне.**
- **Дубль имени внутри паттерна** (2+ одинаковых «Отображаемое имя») — НЕ K=2, а аномалия:
  **в блок уходят только дублирующиеся строки** с пометкой
  `[!] дубль имени: <имя> (N строк) — разобраться: переименовать или поправить «Входит в»/«Состоит из»`.
  Уникальные строки паттерна остаются в шаге.
- **Один тип в разных паттернах** — `[!] тип в N паттернах: <тип> — разобраться` + в блок.
- **В шаг** идут паттерны с уникальными именами: K≥2 — обычный подшаг; K=1 — отдельный подшаг `01.i` (штатная уникальная сущность, НЕ аномалия).
- Порог дробления на вызовы: P > {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ} **или** ΣK > {ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}*10 — по границе паттерна; следующий вызов `{LAST_STEP_NUMBER}` = `01.i`.
- Один гигантский паттерн не влезает — `01.i.1`, `01.i.2`, … `[!] паттерн разрезан: <имя>`.

### «Документы» — Шаги 2…N (`01` / `≥ 02`)
- Вход — фрагмент Схемы.
- **Генерируется НЕСКОЛЬКО шагов за вызов**: от `NN+1` (или `02` при `01`) до конца этапа или предела контекста — что наступит раньше. При этом формируются **несколько независимых CSV-блоков**, каждый из которых содержит не более `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` типов. **Не «ровно один шаг».**
- Строки с «Паттерн» → блок.
- Дробление по объёму; целостность уровня; документ/атрибут атомарны.
- Контейнеры — только в Шаге 0.
- Порядок — сверху вниз.
- Номера — `NN+1`, `NN+2`… **точки запрещены** (в Шагах 2…N).

## Блок «ТРЕБУЮТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ»

После шага(ов), до статистики:
<!-- USER_ACTION_START -->
ТРЕБУЮТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ: нет
<!-- USER_ACTION_END -->
(При наличии аномалий вместо строки «нет» выводится список:
ТРЕБУЮТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ (в шаг не включены):
<Паттерн>|<Тип>
)

Причины попадания:
- дубль имени внутри паттерна (только дублирующиеся строки);
- тип встречается в нескольких паттернах;
- строка с заполненным «Паттерн» в Шагах 2…N.

Правила: профиль `нет`/`00.i` — папка+«Паттерн» K=1 идёт в шаг (не в блок); `0`/`00` — дубли; `≥02` — любое число «Паттерн». Сортировка по паттерну, затем типу. Точные дубли — `[!] дубль`. Пустые — игнорировать. **В Шаге 0 документы (с «Паттерн» или без) в блок НЕ отправляются — они отфильтровываются.**

## Постобработка (пользователь)

| Ситуация | Действие |
|---|---|
| Тип уже в Шаге 1 | удалить |
| Паттерн есть, типа нет | дописать в `01.i` |
| Паттерна нет, типов несколько | новый подшаг `01.N+1` |
| Паттерна нет, тип один | новый шаг `NN+1` |
| Дубль имени | переименовать или поправить «Входит в»/«Состоит из» |

## Правила вывода (СТРОГО)
- Применяй **Правило непрерывной разбивки**: для профиля «Документы» генерируй несколько шагов за вызов; для остальных профилей также автоматически переходи к следующим логическим шагам (например, от Шага 0 к Шагу 1), если позволяет свободное место в контексте.
- Список шагов СТРОГО обрамляется маркерами `<!-- STEPS_CSV_START -->` и `<!-- STEPS_CSV_END -->` на отдельных строках (при СТОП маркеры не выводятся).
- Без markdown-разметки внутри списка.
- **Запрещено**: паттерны/справочники (выход №0.2), `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}`, `{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}`, полный список шагов.
- Вход — не по имени файла.
- Символ `|` внутри предупреждения — **запрещён**.
- В статистике запрещены приближённые значения (~, около, примерно) — только точные числа.
- Маркеры `<!-- USER_ACTION_START -->` / `<!-- USER_ACTION_END -->` и `<!-- STATISTICS_START -->` / `<!-- STATISTICS_END -->` присутствуют всегда (включая СТОП).

## Самопроверка перед отправкой
- Обязательные параметры заполнены: «Шаг» (не пусто, `нет` допустимо), «Имя входного файла» (не пусто).
- Опциональные пустые — считать «нет»/50, не СТОП.
- Профиль вызова определён: `нет`/`00.i` → папки; `0`/`00`/`01.i[.k]` → паттерны; `01`/`≥02` → документы.
- `00.i` трактуется как «Таблица папок», а НЕ «Таблица паттернов».
- `0` = `00` (явно).
- `01` (без точки) — ВСЕГДА «Шаг 1 завершён» → Шаг 2; не `01.i`.
- `01.i` — СТОП, если вход документы («Шаг 1 не завершён»).
- Для профиля «Документы» сгенерировано НЕСКОЛЬКО шагов (не «ровно один»).
- Каждый CSV-блок содержит ≤ `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` типов; при превышении формируется несколько независимых блоков.
- СТОП с сообщением «Контекст превышен» — только если данные не помещаются в окно контекста (не по лимиту типов).
- Каждая строка — **5 колонок**; `|` внутри предупреждения нет.
- `Паттерн` заполнен только в Шаге 1.
- Шаг 1: подшаг = ровно один паттерн (объединение запрещено).
- Шаги 2…N: номера последовательные, без точек.
- ΣK = числу типов в статистике (при СТОП — «не применимо»).
- Баланс строк включает «отфильтровано»: вход = шаг + блок + отфильтровано.
- Баланс паттернов (Шаг 1): P = подшагов + в блоке.
- При разрезанном паттерне: ΣK кусков = K паттерна.
- Шаги 2…N: строки с «Паттерн» — только в блоке.
- При нехватке контекста — СТОП; различать «Контекст не хватает» / «Контекст превышен (ΣK)» / «Вход неполный».
- Есть статистика.
- Маркеры `<!-- STEPS_CSV_START -->` / `<!-- STEPS_CSV_END -->` на отдельных строках (при СТОП — отсутствуют).
- Шаг 0: документы (любые) — отфильтрованы, в блок не идут; папка + «Паттерн» K≥2 — в шаге с пометкой; K=1 — в шаге с пометкой (НЕ в блоке).
- Шаг 1: паттерн с K=1 — отдельный подшаг 01.i (в шаге, НЕ в блоке).
- Шаг 1: K = число РАЗЛИЧНЫХ уникальных имён; дубли имени → в блок только дублирующиеся строки.
- Маркеры `<!-- USER_ACTION_START -->` / `<!-- USER_ACTION_END -->` и `<!-- STATISTICS_START -->` / `<!-- STATISTICS_END -->` присутствуют всегда (включая СТОП).
- Дробление Шага 1: следующий вызов со значением параметра «Шаг» = `01.i`; когда все паттерны покрыты — `01`.
- Профиль «Документы»: каждый следующий вызов — со значением параметра «Шаг» = последний сгенерированный NN; генерируется несколько шагов до предела.
