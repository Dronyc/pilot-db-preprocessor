# 4. Промт №0.4 — создание шаблона

По резюме (раздел 5.5): вход — один файл из `04_Дополнительные данные` (MD) + Описание (MD, справочно); выход — `Выжимка_<имя>.md` + предложение имени от ИИ; предупреждение «КАТЕГОРИЧЕСКИ РЕКОМЕНДУЕТСЯ…». Один шаблон, N запусков (по числу файлов). Используется **до** №0.2.

```markdown
# Промт №0.4: Выжимка дополнительного документа (ГОСТ, регламент)

## Контекст
Ты — ИИ-аналитик, готовящий **выжимку** приложенного документа для последующей передачи генератору (Промты №0.2/№0.3). Полный документ генератору не передаётся — только выжимка.

Документ — ГОСТ, регламент, стандарт или иной нормативный текст. Цель выжимки — извлечь **термины, структуру ЖЦ, правила именования/классификации**, которые повлияют на генерацию настроек БД Pilot-BIM.

**КАТЕГОРИЧЕСКИ РЕКОМЕНДУЕТСЯ произвести подготовку/выжимку данных до передачи генератору.** Без выжимки генератор либо не увидит документ, либо получит его целиком и превысит контекст.

## Проверка файлов
- Документ: {DOC_FILENAME}
- Описание (справочно): {DESCRIPTION_FILENAME}

Если Документа нет — `[!] Отсутствует обязательный файл: <имя>` → **СТОП**.
Если Описания нет — `[!] Отсутствует файл: <имя>` → продолжить (качество ниже).
Если Документ не читается — `НЕ СФОРМИРОВАН: документ не читается` → **СТОП**, не выдумывать.

## Задача
1. Прочитать документ.
2. Извлечь:
   - **термины и определения** (глоссарий) — только те, что встречаются в документе и релевантны ЖЦ ОКС / Pilot-BIM;
   - **структуру ЖЦ** (фазы, стадии, этапы) — если документ её задаёт;
   - **правила именования/классификации** (форматы кодов, префиксы, обязательные поля);
   - **правило ТПР/ТПКР** (если документ его вводит) — что это, когда применяется.
3. Выдать выжимку в формате ниже.
4. **Предложить имя файла** выжимки в конце ответа (см. «Имя выжимки»).

## Формат выжимки

```markdown
# Выжимка: <краткое название документа>

## Источник
- Файл: <DOC_FILENAME>
- Тип: <ГОСТ | регламент | стандарт | иное>
- Дата/версия (если указаны): <...>

## Термины и определения
| Термин | Определение (кратко) | Раздел источника |
|---|---|---|
| ... | ... | ... |

## Структура ЖЦ (если задана документом)
- Фаза 1: <название> — <стадии/этапы>
- Фаза 2: ...

(если документ не задаёт структуру ЖЦ — секция опускается с пометкой «не задана документом»)

## Правила именования / классификации
- <правило 1>
- <правило 2>

(если не заданы — «не заданы документом»)

## Правило ТПР/ТПКР
<что это, когда применяется; если не вводится — «не вводится документом»>

## Что важно для генератора
- <3–7 пунктов: что из документа повлияет на генерацию паттернов/шагов>
```

## Имя выжимки
В конце ответа, после выжимки, отдельной строкой:
```
ПРЕДЛОЖЕНИЕ ИМЕНИ: Выжимка_<краткое_имя_латиницей>.md
```
Имя — латиницей, без пробелов, с префиксом `Выжимка_`. Пример: `Выжимка_GOST_R_10_00_00_05_2025.md`.

**Пользователь сохраняет** выжимку в `02_Подготовка данных\04_Дополнительные данные\` под предложенным (или своим) именем.

## Ограничения
- Не выдумывать термины, которых нет в документе.
- Не включать полный текст документа — только выжимку.
- Не ссылаться на разделы, которых нет.
- Если документ нерелевантен (не про ЖЦ/не про Pilot-BIM) — выдать выжимку с пометкой `[!] документ нерелевантен генератору` и секцией «Что важно для генератора» = «ничего».

## Самопроверка перед отправкой
- Есть секция «Источник».
- Есть «Термины и определения» (таблица).
- Есть «Структура ЖЦ» или пометка «не задана».
- Есть «Правила именования» или пометка.
- Есть «Правило ТПР/ТПКР» или пометка.
- Есть «Что важно для генератора».
- Есть `ПРЕДЛОЖЕНИЕ ИМЕНИ:`.
- Нет полного текста документа.
- Нет выдуманных терминов.

## Как пользователь сохранит результат
1. Скопировать выжимку в `02_Подготовка данных\04_Дополнительные данные\<предложенное_имя>.md`.
2. Повторить для каждого файла в `04_Дополнительные данные` (N запусков).
3. Исходные файлы (PDF/DOCX) остаются в `01_Исходные данные\04_Дополнительные данные` — генератору не передаются.
```

# 5. Напоминание: какая задача и для чего

Из резюме (раздел 4, п.10 и 5.6):
> «Задача "анализ листа «Настройки»" — **отдельным PR** для QWEN-Coder (сначала анализ, потом правки)».

**Для чего:** лист «Настройки» в `Препроцессор_*.xlsm` содержит константы (`{{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}}` = 50, `{STEP1_COMPLETE}`, пути, флаги). Сейчас они **разбросаны** по коду и шаблонам, часть захардкожена. Задача — **проанализировать** лист «Настройки»: какие константы там реально есть, какие используются в коде, какие дублируются, какие отсутствуют. **Правки — потом**, отдельным PR. Сначала — карта «что есть / чего нет», чтобы не менять код вслепую.

# 6. Промт для анализа листа «Настройки»

```markdown
ЗАДАЧА: анализ листа «Настройки» в Препроцессор_*.xlsm (без правок кода).
ЦЕЛЬ: карта констант — что есть на листе, что используется в коде, что дублируется, чего не хватает.

ВХОД:
- Препроцессор_*.xlsm (лист «Настройки», все листы — для контекста).
- Mod_Prompt.bas, Mod_Folders.bas, Mod_Structure.bas, Mod_Util.bas (если есть).
- docs/Spec_Optimization.md, docs/Data_Schema.md.

ЧТО СДЕЛАТЬ:
1. Выписать все строки листа «Настройки»: имя параметра, значение, назначение (если указано).
2. Найти в коде все обращения к листу «Настройки» (поиск по «Настройки», «Settings», «GetSetting»).
3. Сопоставить: параметр листа ↔ использование в коде ↔ использование в шаблонах промтов.
4. Отметить:
   - параметры на листе, которые нигде не используются;
   - параметры, захардкоженные в коде, но отсутствующие на листе;
   - дубли (одно и то же значение в разных местах);
   - параметры, которые нужны по ТЗ, но отсутствуют (например, {STEP1_COMPLETE}, {{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}}).
5. Выдать отчёт в формате таблицы.

ФОРМАТ ОТЧЁТА:
| Параметр | На листе | Значение | Используется в коде | Используется в шаблонах | Проблема |
|---|---|---|---|---|---|

Плюс секции:
- «Не используется на листе» (список);
- «Захардкожено, но нет на листе» (список);
- «Дубли» (список);
- «Отсутствует, но нужно по ТЗ» (список).

ОГРАНИЧЕНИЯ: не менять код, не менять книгу. Только анализ.
ВЕТКА: for-coder/W8-analyze-settings-sheet (только отчёт в docs/, без правок кода).
PR: имя «[W8] Анализ листа Настройки», в описании — ссылка на отчёт.
