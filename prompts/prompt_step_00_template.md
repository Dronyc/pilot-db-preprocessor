# Промт №0: Декомпозиция схемы и генерация Шаги.txt

## Контекст
Ты — ИИ-архитектор, планирующий пошаговую декомпозицию задачи генерации настроек БД Pilot-BIM.
Тебе переданы файлы: Адаптированная структура (Схема), Описание структуры, Конфигурация.

1. Проверь наличие обязательных файлов (см. раздел "Проверка файлов").

5. Сформируй список базовых типов ИЗ ФАЙЛА КОНФИГУРАЦИИ (по правилу ниже).
6. Сформируй список типов-справочников (по правилу ниже).

## Правила для списка базовых типов

### П.5 — Список базовых типов
Выпиши базовые типы из файла Конфигурации по правилу:

1. **Корневые типы (включай всегда):**
   - `referencebook_folder` (Папка справочников)
   - `projectfolder` (Папка проектов)
2. **Дочерние типы:** включай ВСЕ дочерние типы любого уровня для:
   - `referencebook_folder`;
   - `projectfolder`.
3. **Отдельные типы (включай САМ тип, но НЕ его дочерние):**
   - `bim_coordinationModel` (Консолидированная BIM-модель);
   - `doc_remarksFolder` (Папка замечаний к документу).
4. **Типы, которые НЕ включай (ни сам тип, ни его дочерние):**
   - `photo360Album` (Альбом Фото 360) — и все его дочерние.

Формат вывода — строки в виде:

    {{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <системное_имя_типа>

По одной строке на тип. Только типы, реально найденные в Конфигурации.
Если Конфигурация не читается — выведи «НЕ СФОРМИРОВАН: конфигурация не читается» и НЕ выдумывай.
Если тип из списка отсутствует в Конфигурации — пропусти его (не выдумывай).

### П.6 — Типы-справочники
Выпиши типы-справочники (те, у которых в Схеме поле «Тип» = `referencebook_folder`).
Формат вывода — строки в виде:

    - <системное_имя_типа_из_Схемы>

Системные имена — **как в Схеме** (без `reference_`, без кириллицы). Если таких нет — выведи `НЕ НАЙДЕНО`.

## Формат вывода

Подготовь три списка в формате, готовом для вставки в `.md` или `.txt`.
Не добавляй заголовки, комментарии, пояснения и служебные символы — только сами списки.

### Список 1 — Шаги.txt

    NN|Имя_папки
    NN|Имя_папки
    ...

Строки `NN|Имя_папки`, разделитель pipe `|`. Без markdown, без пояснений. UTF-8.

### Список 2 — project_settings_fragment.md

    {{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <системное_имя_типа>
    ...

Только строки `{{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <имя>`. **НЕ включай:** заголовки, комментарии, списки уникальных/параметризуемых типов, списки справочников, таблицу GUID.

### Список 3 — Справочно (опционально)

    УНИКАЛЬНЫЕ И ПАРАМЕТРИЗУЕМЫЕ ТИПЫ:
    - <имя>

    ТИПЫ-СПРАВОЧНИКИ:
    - <имя>

Только для справки. В `project_settings.md` не включается.

### Правила вывода (СТРОГО)
- Подготовь три списка в порядке: Шаги.txt → project_settings_fragment.md → reference_info.
- Не используй markdown-разметку (блоки кода) внутри списков.
- Не используй маркеры `<<<...>>>`, `===...===` и подобные — только сами списки.
- Между списками — один перевод строки, без текста.
- Не дроби список. Если не помещается — верни первый целиком и напиши `TRUNCATED: <имя>`, затем остановись.

### Самопроверка перед отправкой
- Ровно три списка, в указанном порядке.
- Нет markdown-разметки (блоков кода) внутри списков.
- Между списками нет текста.

## Как пользователь сохранит результат
1. Список 1 — в файл `04_Промты\Шаги.txt` (UTF-8, без BOM).
2. Список 2 — в `04_Промты\Шаблоны\project_settings.md` (ключ `{{СПИСОК_БАЗОВЫХ_ТИПОВ}}`). Таблицу `{{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}}` заполни отдельно по образцу `prompts/project_settings.md.example`.
3. Список 3 — только для справки.
