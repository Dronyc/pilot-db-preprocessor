# Промт №0: Декомпозиция схемы и генерация Шаги.txt

## Контекст
Ты — ИИ-архитектор, планирующий пошаговую декомпозицию задачи генерации настроек БД Pilot-BIM.
Тебе переданы файлы: Адаптированная структура (Схема), Описание структуры, Конфигурация.

ПРИМЕЧАНИЕ: в отличие от промтов шагов (где у тебя нет функции сохранения файлов),
здесь ты возвращаешь два файла в виде блоков <<<FILE:имя>>>. Это НЕ сохранение
в репозиторий — пользователь сохранит файлы сам.

## Задача
1. Проверь наличие обязательных файлов (см. раздел "Проверка файлов").
2. Выполни алгоритм декомпозиции (см. раздел "Алгоритм декомпозиции").
3. Сформируй файл Шаги.txt (формат строк: NN|Имя_папки).
4. Сформируй список УНИКАЛЬНЫХ и ПАРАМЕТРИЗУЕМЫХ типов (пометка в списке;
   системные имена — по правилам блока 8.2 Промта шага).
5. Сформируй список базовых типов ИЗ ФАЙЛА КОНФИГУРАЦИИ.
   Формат вывода — готовый фрагмент для project_settings.md:
       {{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <системное_имя_типа>
   По одной строке на тип. Только типы, реально найденные в Конфигурации.
   Если Конфигурация не читается — выведи «НЕ СФОРМИРОВАН: конфигурация
   не читается» и НЕ выдумывай.
6. Сформируй отдельный список типов-справочников с пометкой reference_
   (только пометка для читателя; системные имена — по правилам блока 8.2).
   GUID в этом промте НЕ формируются и НЕ извлекаются (Конфигурация их
   не содержит). Таблицу {{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}} пользователь заполняет
   в project_settings.md (см. prompts/project_settings.md.example).
   В блок 2 таблицу GUID НЕ включай.

- Схема (адаптированная структура): {SCHEMA_FILENAME}
- Описание: {DESCRIPTION_FILENAME}

## Формат вывода
Верни ответ РОВНО двумя блоками с маркерами <<<FILE:...>>> / <<<END:...>>>.
Подробные правила — в конце этого раздела.

### Блок 1 — Шаги.txt
Содержимое: строки NN|Имя_папки, разделитель pipe "|". Без markdown,
без пояснений. UTF-8.
Пользователь сохранит в 04_Промты\Шаги.txt.

### Блок 2 — project_settings_fragment.md
Содержимое — ТОЛЬКО один ключ (готовый фрагмент для вставки):
    {{СПИСОК_БАЗОВЫХ_ТИПОВ}} = <системное_имя_типа>
Таблицу {{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}} пользователь заполняет отдельно
в project_settings.md (см. prompts/project_settings.md.example).

### Правила блоков (СТРОГО)
- РОВНО два блока, в порядке: Шаги.txt → project_settings_fragment.md.
- Каждый блок: <<<FILE:имя>>> ... <<<END:имя>>> (имя совпадает).
- ВНУТРИ блока НЕТ ``` и НЕТ <<<...>>>.
- МЕЖДУ блоками — ровно один перевод строки, без текста.
- НЕ дроби блок. Если не помещается — верни первый целиком и
  <<<TRUNCATED:имя>>>, затем остановись.
- Механизм скачивания (если есть) — опционально; формат блоков
  не меняется.

### Самопроверка перед отправкой
Перед отправкой ответа проверь:
- Ровно 2 маркера <<<FILE:...>>> и ровно 2 <<<END:...>>>.
- Имена в FILE и END совпадают попарно.
- Внутри блоков нет ``` и нет <<<...>>>.
- Между блоками нет текста.
Если хоть одно условие не выполнено — исправь ответ и проверь снова.

## Как пользователь сохранит результат
1. Скопируй содержимое между <<<FILE:Шаги.txt>>> и <<<END:Шаги.txt>>>
   в файл 04_Промты\Шаги.txt (UTF-8, без BOM).
2. Скопируй содержимое между <<<FILE:project_settings_fragment.md>>>
   и <<<END:project_settings_fragment.md>>> и вставь в
   04_Промты\Шаблоны\project_settings.md (ключ {{СПИСОК_БАЗОВЫХ_ТИПОВ}};
   таблицу {{ТАБЛИЦА_ИЗВЕСТНЫХ_GUID}} заполни отдельно по образцу
   prompts/project_settings.md.example).
