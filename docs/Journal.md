# Журнал работ проекта

Назначение: единый источник информации о фактическом состоянии проекта для всех участников — владельца, DeepSeek (оркестратор), QWEN-Coder и ревьюеров.

## Правила ведения

1. Запись добавляется при закрытии задачи (OPT-xx / W<N>), при изменении планов и при важных решениях.
2. Записи не редактируются и не удаляются — исправления оформляются новой записью со ссылкой на предыдущую (тот же принцип, что у промтов в `/prompts/`).
3. Текущий статус задач ведётся в колонке «Статус» таблицы задач в `Spec_Optimization.md`; журнал объясняет, почему задача закрыта или заблокирована.
4. Каждая запись ссылается на PR или коммит, если они есть.

## Шаблон записи

```text
### ГГГГ-ММ-ДД — OPT-xx (W<N>) — краткое название
- Статус: выполнено / заблокировано / частично.
- Что сделано: 1–3 предложения.
- Кто: QWEN-Coder (PR #[номер]) / владелец вручную / DeepSeek (документы).
- Как проверялось: тесты из Spec_Optimization.md («После OPT-xx») + ручная проверка в книге.
- Принятые решения: что и почему решено.
- Открытые вопросы: что мешает или требует решения владельца.
- Следующий шаг: какая задача идёт дальше.
```

### 2026-11-03 — T3.1 — Лист «Настройки»: 6 полей, исправление Validation, чтение MaxTypesPerTable/ProjectRoot
- **Статус:** выполнено.
- **Что сделано:** `Mod_Util.EnsureSettingsSheet` приведён к 6 полям B2:B7 (ProjectRoot, CheckMode, AutoOpenResults, PromptGenVersion, PromptFixVersion, MaxTypesPerTable); Validation навешан строго на свои ячейки (H1: CheckMode→B3, AutoOpenResults→B4, MaxTypesPerTable→B7 целое >= 1; правило с B2 снимается); именованные диапазоны создаются для всех 6 полей без переопределения существующих; защита листа — разблокированы B2:B7. `GetProjectRoot` теперь читает ProjectRoot из «Настроек», при пустом значении — ThisWorkbook.Path (H2, комментарий шапки приведён в соответствие); добавлена `GetSettingLong(name, defaultValue)` с предупреждением U007 при пустом/некорректном значении (код зарегистрирован в реестре комментария модуля). `Mod_Prompt.GenerateStepZeroPrompt` подставляет `{ЛИМИТ_ТИПОВ_В_ТАБЛИЦЕ}` через `GetSettingLong("MaxTypesPerTable", 50)` вместо константы (H3). Поля CheckMode/AutoOpenResults/PromptGenVersion/PromptFixVersion не удалены; их неиспользование зафиксировано информационной записью WriteLog в EnsureSettingsSheet (H4).
- **Кто:** QWEN-Coder (PR «[T3.1] Лист Настройки: 6 полей, исправление Validation, чтение MaxTypesPerTable/ProjectRoot»).
- **Как проверялось:** тест «После T3.1» из Spec_Optimization.md (раздел 3): состав полей B2:B7, привязка Validation, имена диапазонов, поведение GetProjectRoot/GetSettingLong, подстановка лимита в Mod_Prompt; проверка неповторной перезаписи значений по коду цикла defaults (заполняются только пустые ячейки).
- **Принятые решения:** ProjectRoot остаётся пустым по умолчанию (пусто = папка книги — обратная совместимость); значение по умолчанию 50 вынесено в публичную константу `DEFAULT_MAX_TYPES_PER_TABLE`; U007 — предупреждение (не ошибка), имя/лист не найдены → default без записи в журнал (штатное состояние до первого запуска EnsureSettingsSheet).
- **Открытые вопросы:** реальное использование CheckMode/AutoOpenResults/PromptGenVersion/PromptFixVersion в логике — за отдельными задачами; шаблоны Промтов №0.2/№0.3 (`prompt_step_00_*.md`) пока заполняются пользователем вручную, кодом формируются Промт №0 (prompt_step_00_template.md) и промты шагов.
