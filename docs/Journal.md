# Журнал работ проекта

Назначение: единый источник информации о фактическом состоянии проекта для всех участников — владельца, DeepSeek (оркестратор), QWEN-Coder и ревьюеров.

## Правила ведения

1. Запись добавляется при закрытии задачи (OPT-xx / W<N>), при изменении планов и при важных решениях.
2. Записи не редактируются и не удаляются — исправления оформляются новой записью со ссылкой на предыдущую (тот же принцип, что у промтов в `/prompts/`).
3. Текущий статус задач ведётся в колонке «Статус» таблицы задач в `Spec_Optimization.md`; журнал объясняет, почему задача закрыта или заблокирована.
4. Каждая запись ссылается на PR или коммит, если они есть.

## Шаблон записи

```text
### ГГГГ-ММ-ДД — OPT-xx (W<N>) — краткое название
- Статус: выполнено / заблокировано / частично.
- Что сделано: 1–3 предложения.
- Кто: QWEN-Coder (PR #[номер]) / владелец вручную / DeepSeek (документы).
- Как проверялось: тесты из Spec_Optimization.md («После OPT-xx») + ручная проверка в книге.
- Принятые решения: что и почему решено.
- Открытые вопросы: что мешает или требует решения владельца.
- Следующий шаг: какая задача идёт дальше.
```

### 2026-11-03 — T3.1-fix — Mod_Util: чтение значений настроек через RefersToRange.Value
- **Статус:** выполнено (правка кода по замечаниям ревью T3.1).
- **Что сделано:** в `Mod_Util.bas` точечно исправлены два места: `GetProjectRoot` читает значение именованного диапазона ProjectRoot через `nm.RefersToRange.Value` вместо `nm.Value` (строка определения имени); `GetSettingLong` читает `ThisWorkbook.Names(name).RefersToRange.Value` вместо `Names(...).Value`. В обоих местах добавлена локальная обработка ошибок (`On Error Resume Next` → проверка `Err.Number` → `Err.Clear` → `On Error GoTo 0`): при ошибке/недоступности значение считается пустым. Удалён ставший ненужным код отсечения хвоста после `";"` (актуален только для строки определения имени).
- **Кто:** QWEN-Coder (ветка/PR прежние: «[T3.1] Лист Настройки: 6 полей, исправление Validation, чтение MaxTypesPerTable/ProjectRoot»).
- **Как проверялось:** статическая проверка кодом без запуска Excel: в изменённых местах нет обращений `Names(...).Value` (только `RefersToRange.Value`); локальная обработка ошибок присутствует в обоих местах; fallback-логика сохранена (пустой/недоступный ProjectRoot → ThisWorkbook.Path; пустое/некорректное числовое значение → defaultValue, для MaxTypesPerTable → 50 + WriteWarning U007); сигнатуры публичных функций не изменены; других процедур правка не коснулась (diff: только GetProjectRoot и GetSettingLong). Тест-сценарий в Excel (EnsureSettingsSheet / заполнение B2 и B7 / проверка возвратов и записей U007 в журнале) передан пользователю.
- **Принятые решения:** при недоступном `RefersToRange` в `GetSettingLong` запись `U007` («настройка пуста») выполняется как раньше — штатное предупреждение о значении по умолчанию; тихий выход без предупреждения сохранён только для случая «лист «Настройки» отсутствует» (проверка листа до чтения, вне изменённых мест).
- **Открытые вопросы:** подтверждение в Excel выполняет пользователь (запуск сценария теста «После T3.1»).
- **Следующий шаг:** приёмка T3.1/T3.1-fix владельцем в книге Excel.
