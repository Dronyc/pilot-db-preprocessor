# Spec_Dispatcher.md

## Раздел 1. НАЗНАЧЕНИЕ

Препроцессор структуры БД Pilot — это файл `Препроцессор_структуры_БД_Pilot.xlsm` с макросами, который подготавливает типы и атрибуты для импорта в конфигурацию Pilot. Инструмент предназначен для архитектора, аналитика и специалиста по конфигурации, который работает через кнопки на главном листе «Препроцессор», не редактируя служебные листы и сводные данные вручную.

На выходе Препроцессор создаёт рабочую структуру папок, проверяет исходные данные, собирает плоскую таблицу схемы, формирует сводную таблицу типов и атрибутов, ведёт реестр типов и реестр покрытия, готовит промты для внешнего исполнителя на основе искусственного интеллекта, сохраняет готовые промты, пишет логи и показывает ошибки и предупреждения последней сборки.

## Раздел 3. ПРАВИЛА РАБОТЫ С ПАПКАМИ

- Кнопка «Создать папки проекта» создаёт корневую структуру (включая подпапку `04_Промты/Шаблоны/`), копирует `.md` шаблоны промтов из внешней папки `Шаблоны/` (рядом с `.xlsm`) в `04_Промты/Шаблоны/`, создаёт папку `Шаг_00_Скелет/` и файл `Промт_шаг_00.md` в папке `03_Результаты генерации/04_Промты_готовые/`.
- Валидация входных данных (`CheckSourceFolders`, кнопка «Проверить исходные данные») проверяет поддерживаемые расширения исходных файлов:
  - `01_Исходные данные/01_Схема/` — Схема: файл `*.xlsx`;
  - `01_Исходные данные/02_Описание/` — Описание: файл `*.docx` или иной текстовый файл;
  - `01_Исходные данные/03_Конфигурация/` — Конфигурация: файл `*.xml` или `*.pilotcfx`.
- Поддерживаемые расширения: Схема (*.xlsx), Описание (*.docx или иной текстовый), Конфигурация (*.xml или *.pilotcfx). При несоответствии форматов выводится предупреждение и запись в лог (код F005).
- Остальные папки шагов (`Шаг_01`, `Шаг_NN`, `Шаг_99` и любые промежуточные) **не создаются заранее**. Они создаются только по факту формирования промта соответствующего шага.
- Препроцессор **никогда не удаляет** папки и файлы. Любое удаление выполняется только пользователем вручную.
- При инициализации шага VBA создаёт в папке `Шаг_NN` 2 служебных файла для передачи ИИ: `Промт_шаг_NN.md` и `Фрагмент_схемы_шаг_NN.csv`.
- Результатом работы ИИ должны быть ровно 2 файла, которые размещаются в той же папке: `*_etap_NN_types.xlsx` (типы) и `*_etap_NN_attributes.xlsx` (атрибуты).
- VBA проверяет наличие именно этих 2 файлов результатов. Определение типа файла выполняется по заголовкам первой строки:
  - если есть «Системное имя типа» и «Видимое имя типа», файл считается файлом типов;
  - если есть «Системное имя типа» и `name`, файл считается файлом атрибутов.
- Если файлов результатов в папке шага не ровно два, Препроцессор показывает предупреждение и останавливает работу.
- Правки вносятся только в файлы шагов.
- Ручная правка сводной таблицы запрещена.

## Раздел 6. ЛИСТ «README»

Лист `Readme` содержит текст инструкции пользователя. Кнопка «Обновить Readme» формирует файл `Readme.md` на основе актуального содержимого листа. Состав инструкции соответствует разделу 10 настоящей спецификации.

Модуль документации `Mod_Docs` (`UpdateReadme`) формирует актуальный файл `Readme.md`. Readme должен содержать раздел "Восстановление шаблонов" с полными текстами всех 4 шаблонов (prompt_step_00_template.md, prompt_step_template_v1.md, prompt_fix_v1.0.md, prompt_settings_template.md) и раздел "Workflow". При ненайденном шаблоне в Readme вставляется заглушка "[Файл не найден]" и пишется предупреждение D003 в лог (без прерывания работы).

Дополнительно в конец файла `Readme.md` добавляются два раздела:

- **«Workflow»** — краткое описание процесса работы Препроцессора (последовательность шагов от создания структуры папок до финального аудита).
- **«Восстановление шаблонов»** — **полные тексты всех 4 шаблонов промтов** из папки `04_Промты/Шаблоны/`:
  - `prompt_step_00_template.md`;
  - `prompt_step_template_v1.md`;
  - `prompt_fix_v1.0.md`;
  - `prompt_settings_template.md`.

  Если файл шаблона не найден или не читается, вместо его текста подставляется `[Файл не найден]`, в лог записывается предупреждение `D003`, формирование Readme продолжается без прерывания.

## Раздел 8. ЛОГИКА ОПРЕДЕЛЕНИЯ ТЕКУЩЕГО ШАГА

Шаги определяются автоматически по колонке «№шага/подшага» листа «Адаптированная_структура». ## Раздел 10. КОДЫ ОШИБОК

Единый справочник кодов ошибок и предупреждений Препроцессора:

- T### — ошибки типов (T = Type). Используются для проблем с листом «Типы» и файлами типов. Примеры: T005 — не удалось загрузить файл типов, T018 — ошибка этапа проверки иерархии.
- A### — ошибки атрибутов (A = Attribute). Используются для проблем с листом «Атрибуты» и файлами атрибутов. Примеры: A017 — не удалось загрузить файл атрибутов.
- R### — ошибки реестров (R = Registry). Используются для проблем построения и записи реестров. Примеры: R001 — в книге не найден лист «Типы», R002 — в книге не найден лист «Атрибуты», R003 — ошибка записи файла реестра, R004 — ошибка создания папки реестров, R005 — реестры не построены (не вызван BuildRegistries) или непредвиденная ошибка при работе с реестрами.
- D### — ошибки модуля документации `Mod_Docs` (D = Docs). Примеры: D001 — не найден лист «Readme», D002 — ошибка создания папки `docs` или записи файла `Readme.md`, **D003 — шаблон не найден в Readme** (файл шаблона промтов отсутствует или не читается при формировании раздела «Восстановление шаблонов»; выводится как предупреждение, вместо текста шаблона подставляется `[Файл не найден]`).
- F### — коды модуля работы с папками `Mod_Folders` (F = Folder). Используются для системных ошибок операций с файлами и папками:
  - **F001** — папка проекта не определена (книга `.xlsm` не сохранена);
  - **F002** — ошибка создания папки (`MkDir`);
  - **F003** — ошибка копирования файла шаблона (`FileCopy`) из внешней папки `Шаблоны/` в `04_Промты/Шаблоны/`;
  - **F004** — внешняя папка `Шаблоны` не найдена (предупреждение: шаблоны промтов не скопированы);
  - F005 — несоответствие исходных файлов в `CheckSourceFolders` (а также непредвиденная ошибка проверки).
- P### — коды модуля промтов `Mod_Prompt` (P = Prompt):
  - **P001** — устаревший (Шаги.txt упразднён в W-CLEANUP-STEP0);
  - **P002** — ошибка формирования промта шага;
  - **P003** — ошибка формирования промта исправления;
  - **P004** — устаревший (Промт №0 формируется через MakeNextStepPrompt);
  - **P005** — ошибка сохранения (записи) текстового файла в UTF-8;
  - **P006** — ошибка чтения текстового файла (или пустой результат чтения) с автоопределением кодировки; фиксируется как предупреждение, выполнение не прерывается;
  - **P007** — ошибка генерации аналитических промтов (процедура `GenerateAnalyticalPrompts_Click`, промты 00_1 / 00_4);
  - **P008** — предупреждение: нераспознанный формат ответа ИИ (отсутствуют ожидаемые маркеры);
  - **P009** — ошибка обработки отдельного файла (изолированная ошибка, не прерывающая цикл);
  - **P010** — критическая ошибка процедуры разбора ответа ИИ (прерывает выполнение);
  - **P011** — предупреждение: Коллизия при архивации: файл переименован с суффиксом _yyyy-mm-dd_hhnnss.
  - **P012** — Ошибка перемещения файла оператором Name.

## Раздел 11. ПРАВИЛА РЕЕСТРОВ

- Реестры формируются только при сборке сводной таблицы в черновом или строгом режиме.
- Отдельной кнопки для формирования реестров нет.
- Файл `Реестр_типов.txt` содержит все системные имена из листа «Типы» сводной таблицы.
- Файл `Реестр_покрытия.txt` содержит типы, у которых на листе «Атрибуты» есть хотя бы одна строка.
- Файлы реестров перезаписываются при каждой сборке.
- Одновременно с файлами обновляются листы `_Реестр_типов` и `_Реестр_покрытия` внутри Препроцессора.

## Раздел 12. ПРАВИЛА ПРОМТОВ (логика Mod_Prompt)

### Шаблоны промтов

Шаблоны промтов хранятся в подпапке `04_Промты/Шаблоны/`:
- `prompt_step_00_1_template.md` (Промт №0.1 — базовые типы из Конфигурации);
- `prompt_step_00_2_template.md` (Промт №0.2 — паттерны);
- `prompt_step_00_3_template.md` (Промт №0.3 — распределение по шагам);
- `prompt_step_00_4_template.md` (Промт №0.4 — выжимка документа);
- `prompt_step_template_v1.md` (промт отдельного шага);
- `prompt_fix_v1.0.md` (промт исправления ошибок);
- `prompt_settings_template.md` (шаблон настроек).

Шаблон `prompt_step_00_template.md` (Промт №0 — декомпозиция) **отменён** и перемещён в `prompts/archive/`.

### Рабочие папки промтов

- Промты 00_1 сохраняются в `01_Исходные данные/03_Конфигурация/`.
- Промты 00_4 сохраняются в `01_Исходные данные/02_Описание/` и `01_Исходные данные/04_Дополнительные данные/`.
- Промты 00_2 и 00_3 сохраняются в `02_Подготовка данных/05_Фрагменты шагов/`.
- Ответы ИИ (таблицы) сохраняются пользователем в `02_Подготовка данных/05_Фрагменты шагов/`.
- Выжимки (результаты 00_4) сохраняются пользователем в `02_Подготовка данных/02_Описание/` и `02_Подготовка данных/04_Дополнительные данные/`.
- Обработанные ответы и промты перемещаются в `02_Подготовка данных/Архив/`.
- Готовые промты шагов сохраняются в `03_Результаты генерации/04_Промты_готовые/`.

### Файл Шаги.txt

Файл `Шаги.txt` **не создаётся и не используется**. Список шагов определяется из столбца «№шага/подшага» в «Адаптированной структуре». Имя папки шага: `Шаг_NN` (точка в номере сохраняется, например `Шаг_00.1`, `Шаг_01.5`).

### Кнопка «Сгенерировать аналитические промты»

- Генерирует промт 00_1 в `01_Исходные данные/03_Конфигурация/` с именем `Prompt_<имя_конфигурации>.md`.
- Для каждого файла в `01_Исходные данные/02_Описание/` генерирует промт 00_4 с именем `Prompt_<имя_файла>.md`.
- Для каждого файла в `01_Исходные данные/04_Дополнительные данные/` генерирует промт 00_4 с именем `Prompt_<имя_файла>.md`.
- Обрабатываются все файлы в папках.
- Существующие промты пропускаются.
- После генерации ставит «Выжимки и анализ конфигурации» = «Да».

### Кнопка «Сформировать таблицы (00_2 / 00_3)» → **CommandGenerateTables**

- При «Разбивка на паттерны» = «Нет»: генерирует промт 00_2 в `02_Подготовка данных/05_Фрагменты шагов/` с именем `Prompt_00_2_iter<N>.md`.
- При «Разбивка на паттерны» = «Да»: генерирует промт 00_3 в `02_Подготовка данных/05_Фрагменты шагов/` с именем `Prompt_00_3_iter<N>.md`.
- Номер итерации `<N>` определяется сканированием `05_Фрагменты шагов` и `Архив`.
- Работа идёт итерациями.

### Кнопка «Разобрать ответ ИИ»

- Сканирует `02_Подготовка данных/05_Фрагменты шагов/`.
- Пропускает файлы, имя которых начинается с `Prompt_`.
- Автоматически определяет формат по содержимому:
  - `{{СПИСОК_БАЗОВЫХ_ТИПОВ}} = ...` → обновление `project_settings.md`.
  - `Паттерн|Типы|Количество` → заполнение столбца «Паттерн» в «Адаптированной структуре».
  - `NN|типы|K|паттерн|предупреждение` → заполнение «№шага/подшага», предупреждения → «Аномалия».
- Парсер **дополняет** данные: обновляет только строки из файла, не трогая остальные.
- Перемещает в `Архив` обработанный файл ответа и все файлы `Prompt_00_2_iter*.md` / `Prompt_00_3_iter*.md`.
- После успешного парсинга 00_3, если все строки получили номер шага → автоматически «Разбивка на шаги» = «Да».

### Кнопка «Сделать промт следующего шага»

- Активна только при «Разбивка на шаги» = «Да».
- Блокируется с предупреждением, если в `02_Подготовка данных/02_Описание` ИЛИ `02_Подготовка данных/03_Конфигурация` нет файлов.
- Предупреждение (без блокировки) для пустой `02_Подготовка данных/04_Дополнительные данные`, только если в `01_Исходные данные/04_Дополнительные данные` есть файлы.
- Сканирует папки в `03_Результаты генерации/01_По шагам/`, находит максимальный номер.
- Берёт следующий номер из «Адаптированной структуры».
- Создаёт папку `Шаг_NN`, помещает промт шага и фрагмент схемы (CSV с заголовками, фильтрованный по номеру шага).
- В шаблоне промта шага указывается наличие выжимок; файлы выжимок передаются пользователем отдельно.

### Кодировки

Все текстовые файлы (шаблоны `.md`, реестры `.txt`, готовые промты) читаются и пишутся в UTF-8. При чтении выполняется автоопределение кодировки: сначала UTF-8, при неудаче — fallback на Windows-1251 (ANSI). Ошибки записи в UTF-8 фиксируются кодом `P005`, ошибки/пустые результаты чтения — предупреждением `P006`.

### Плейсхолдеры промта шага

- `{NN}` — номер шага;
- `{STEP_NAME}` — имя папки шага;
- `{REGISTRY_TYPES}` — содержимое `Реестр_типов.txt`;
- `{REGISTRY_COVERAGE}` — содержимое `Реестр_покрытия.txt`;
- `{SCHEMA}` — фрагмент плоской таблицы схемы из «Адаптированной структуры» (фильтр по номеру шага);
- `{ERRORS}` — список ошибок из листа «Ошибки» (для промта исправления);
- `{SCHEMA_FILENAME}` — путь к артефакту схемы;
- `{DESCRIPTION_FILENAME}` — путь к описанию;
- `{EXTRA_DATA_LIST}` — список имён файлов дополнительных данных.

Если в шаблоне плейсхолдер отсутствует — он игнорируется. Если данных нет — подставляется пустая строка и пишется предупреждение в лог.

## Раздел 13. ПРАВИЛА РАБОТЫ С GITHUB

- Репозиторий проекта: `pilot-db-preprocessor`.
- Ветка `main` защищена. Прямой пуш в `main` запрещён.
- `QWEN-Coder` работает в ветке `for-coder`.
- Запрос на слияние создаётся на основе ветки `for-coder`.
- Промты хранятся по принципу: каждая версия — новый файл в папке `/prompts/`.
- Старые версии промтов не удаляются.
- Файл `/prompts/CHANGELOG.md` ведёт историю версий промтов.
- Код VBA в формате `.bas` хранится в корне репозитория и обновляется через слияние веток. Автор правок в файлах `*.bas` — `QWEN-Coder`, ревьюер — `QWEN`.
- Настройка `CODEOWNERS`:
  - `/prompts/` и `/docs/` требуют ревью `QWEN`;
  - `*.bas` требуют ревью `QWEN`.

## Раздел 14. ГРАНИЦЫ ОТВЕТСТВЕННОСТИ

- Препроцессор не правит исходные файлы.
