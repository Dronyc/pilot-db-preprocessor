# Spec_Dispatcher.md

## Раздел 1. НАЗНАЧЕНИЕ

Препроцессор структуры БД Pilot — это файл `Препроцессор_структуры_БД_Pilot.xlsm` с макросами, который подготавливает типы и атрибуты для импорта в конфигурацию Pilot. Инструмент предназначен для архитектора, аналитика и специалиста по конфигурации, который работает через кнопки на главном листе «Препроцессор», не редактируя служебные листы и сводные данные вручную.

На выходе Препроцессор создаёт рабочую структуру папок, проверяет исходные данные, собирает плоскую таблицу схемы, формирует сводную таблицу типов и атрибутов, ведёт реестр типов и реестр покрытия, готовит промты для внешнего исполнителя на основе искусственного интеллекта, сохраняет готовые промты, пишет логи и показывает ошибки и предупреждения последней сборки.

## Раздел 3. ПРАВИЛА РАБОТЫ С ПАПКАМИ

- Кнопка «Создать папки проекта» создаёт корневую структуру, папку `Шаг_00_Скелет/` и файл `Промт_шаг_00.md` в папке `03_Результаты генерации/04_Промты_готовые/`.
- Остальные папки шагов (`Шаг_01`, `Шаг_NN`, `Шаг_99` и любые промежуточные) **не создаются заранее**. Они создаются только по факту формирования промта соответствующего шага.
- Препроцессор **никогда не удаляет** папки и файлы. Любое удаление выполняется только пользователем вручную.
- В папке `Шаг_NN` должно быть ровно 2 файла: один с типами и один с атрибутами.
- Определение типа файла выполняется по заголовкам первой строки:
  - если есть «Системное имя типа» и «Видимое имя типа», файл считается файлом типов;
  - если есть «Системное имя типа» и `name`, файл считается файлом атрибутов.
- Если файлов в папке шага больше двух, Препроцессор показывает предупреждение и останавливает работу.
- Правки вносятся только в файлы шагов.
- Ручная правка сводной таблицы запрещена.

## Раздел 4. ЛИСТ «ПРЕПРОЦЕССОР» — 12 кнопок

| № | Кнопка | Что делает | Процедура VBA | Что пишет в лог | Что при ошибке |
|---:|---|---|---|---|---|
| 1 | Создать папки проекта | Создаёт корневую структуру, папку `Шаг_00_Скелет/` и файл `Промт_шаг_00.md` в `04_Промты_готовые/` | `CreateProjectFolders` | Список созданных папок и файла | `MsgBox` с текстом ошибки |
| 2 | Проверить исходные данные | Показывает, какие файлы найдены в папках `01_Исходные данные/`, и какие файлы отсутствуют | `CheckSourceFiles` | Найденные и отсутствующие файлы | `MsgBox` с текстом ошибки |
| 3 | Собрать плоскую таблицу из «Схемы» | Собирает плоскую таблицу из исходной схемы и подготавливает её для анализа | `BuildFlatStructure` | Количество узлов и аномалий | `MsgBox` с текстом ошибки |
| 4 | Повторный анализ преобразованного | Выполняет только анализ уже преобразованной плоской таблицы без пересборки | `RecheckFlatTable` | Количество замечаний | `MsgBox` с текстом ошибки |
| 5 | Собрать типы и атрибуты (черновик) | Собирает сводную таблицу и реестры в черновом режиме | `ValidateAndAssemble(True)` | Количество типов, атрибутов и ошибок | `MsgBox` с текстом ошибки |

| 10 | Открыть папку Логи | Открывает папку `05_Логи/` в проводнике | `OpenLogsFolder` | Путь к папке логов | `MsgBox` с текстом ошибки |
| 11 | Обновить Readme | Формирует актуальный файл `Readme.md` | `UpdateReadme` | Путь к файлу `Readme.md` | `MsgBox` с текстом ошибки |

## Раздел 8. ФАЙЛ ШАГИ.TXT

Полный пример содержимого:

```text

01 = Шаг_01_Универсальные
02 = Шаг_02_Фаза_0_и_1_1
03 = Шаг_03_1_2_1_3
04 = Шаг_04_2_1
05 = Шаг_05_2_2
06 = Шаг_06_2_3
07 = Шаг_07_2_4
08 = Шаг_08_2_5
09 = Шаг_09_2_6
10 = Шаг_10_2_7
11 = Шаг_11_2_8_1
12 = Шаг_12_2_8_2
13 = Шаг_13_2_8_3
14 = Шаг_14_2_8_4
```

Назначение файла `Шаги.txt`: единственный источник порядка и имён шагов. Количество шагов не является константой и может изменяться. Если промт-генератор меняет декомпозицию, правится только файл `Шаги.txt`.

## Раздел 9. ЛОГИКА ОПРЕДЕЛЕНИЯ ТЕКУЩЕГО ШАГА

- Текущий шаг — это последняя существующая папка `Шаг_*` в `03_Результаты генерации/01_По шагам/` согласно порядку из файла `Шаги.txt`.
- Сводная таблица собирается накопительно из всех непустых папок шагов от `Шаг_00_Скелет` до текущего шага включительно.
- Следующий шаг — это шаг из файла `Шаги.txt`, который идёт сразу за текущим.
- Если следующий шаг не найден в `Шаги.txt`, но в `03_Результаты генерации/01_По шагам/` есть непустая папка с номером большим, чем у текущего шага, Препроцессор добавляет новую строку в `Шаги.txt`, создаёт папку этого шага и формирует промт.
- Если дополнительных папок с большим номером нет, формируется файл `Промт_финального_аудита.md` и создаётся папка `Шаг_99_Финал/`.

## Раздел 10. СОДЕРЖАНИЕ README

Файл `Readme.md` должен содержать следующие разделы:

- Назначение Препроцессора.
- Требования к среде: Excel 2016 или выше, макросы разрешены.
- Структура папок проекта в виде дерева.
- Требования к исходным файлам по папкам.
- Пошаговый сценарий работы: 12 кнопок по порядку.
- Расшифровка листов результата.
- Типовые ошибки и действия пользователя.
- Правило: правки вносятся только в файлы шагов, не в сводную таблицу.
- Ограничения: Препроцессор не вызывает внешний искусственный интеллект, не правит исходные файлы, не удаляет папки и файлы.
- Порядок обновления промтов: локально хранится только актуальная версия, история хранится в GitHub в папке `/prompts/`.

## Раздел 11. КОДЫ ОШИБОК

Единый справочник кодов ошибок и предупреждений Препроцессора:

- T### — ошибки типов (T = Type). Используются для проблем с листом «Типы» и файлами типов. Примеры: T005 — не удалось загрузить файл типов, T018 — ошибка этапа проверки иерархии.
- A### — ошибки атрибутов (A = Attribute). Используются для проблем с листом «Атрибуты» и файлами атрибутов. Примеры: A017 — не удалось загрузить файл атрибутов.
- R### — ошибки реестров (R = Registry). Используются для проблем построения и записи реестров. Примеры: R001 — в книге не найден лист «Типы», R002 — в книге не найден лист «Атрибуты», R003 — ошибка записи файла реестра, R004 — ошибка создания папки реестров, R005 — реестры не построены (не вызван BuildRegistries) или непредвиденная ошибка при работе с реестрами.
- F### — ошибки файловых операций (F = File). Используются для системных ошибок чтения/записи файлов и папок. Примеры: F001 — не удалось открыть файл, F004 — не удалось сохранить сводную, F005 — не удалось создать папку.

## Раздел 12. ПРАВИЛА РЕЕСТРОВ

- Реестры формируются только при сборке сводной таблицы в черновом или строгом режиме.
- Отдельной кнопки для формирования реестров нет.
- Файл `Реестр_типов.txt` содержит все системные имена из листа «Типы» сводной таблицы.
- Файл `Реестр_покрытия.txt` содержит типы, у которых на листе «Атрибуты» есть хотя бы одна строка.
- Файлы реестров перезаписываются при каждой сборке.
- Одновременно с файлами обновляются листы `_Реестр_типов` и `_Реестр_покрытия` внутри Препроцессора.

## Раздел 13. ПРАВИЛА ПРОМТОВ

- Шаблоны промтов хранятся в папке `04_Промты/`:
  - `prompt_generator_v7.13.md`;
  - `prompt_fix_v1.0.md`;
  - `prompt_step_template_v1.md`.
- Готовые промты сохраняются в папке `03_Результаты генерации/04_Промты_готовые/`.
- Кнопка «Сделать промт следующего шага»:
  - находит следующий шаг по файлу `Шаги.txt`;
  - создаёт папку этого шага (только в момент формирования промта);
  - подставляет в шаблон оба реестра и фрагмент схемы;
  - сохраняет результат как `Промт_шаг_NN.md`.
- Кнопка «Сделать промт исправления ошибок»:
  - читает лист «Ошибки» последней сводной таблицы;
  - если ошибок нет, сообщает об этом и ничего не формирует;
  - если ошибки есть, подставляет ошибки, оба реестра и фрагмент схемы текущего шага;
  - сохраняет результат как `Промт_исправление_шаг_NN.md`.
- Для финала формируется файл `Промт_финального_аудита.md` в папке `04_Промты_готовые/` и создаётся папка `Шаг_99_Финал/`.

Плейсхолдеры, используемые при подстановке:
- `{NN}` — номер шага;
- `{STEP_NAME}` — имя папки шага;
- `{REGISTRY_TYPES}` — содержимое `Реестр_типов.txt`;
- `{REGISTRY_COVERAGE}` — содержимое `Реестр_покрытия.txt`;
- `{SCHEMA}` — фрагмент плоской таблицы схемы;
- `{ERRORS}` — список ошибок из листа «Ошибки» (для промта исправления).
Если в шаблоне плейсхолдер отсутствует — он игнорируется.
Если данных нет — подставляется пустая строка и пишется предупреждение в лог.
