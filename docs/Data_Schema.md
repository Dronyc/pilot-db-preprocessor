# Схема входных данных

Назначение: текстовое описание бинарных входных файлов, чтобы QWEN-Coder и DeepSeek могли писать и проверять код парсеров, не имея доступа к самим файлам (`xlsx` и `docx` в репозиторий не попадают — это правильно, их место описывается здесь).

> Разделы, помеченные «ЗАПОЛНИТЬ», заполняет владелец по фактическим файлам. После заполнения файл — источник правды по данным для всех агентов.

## 1. Структура.xlsx (источник: «Схема»)

**ЗАПОЛНИТЬ**: перечислить листы и колонки. Формат для каждого листа:

| Лист | № колонки | Заголовок | Тип данных | Пример | Правила / словарь значений |
|---|---|---|---|---|---|
| ЗАПОЛНИТЬ | | | | | |

Особенности, важные для кода (**ЗАПОЛНИТЬ**):
- где хранится иерархия («Входит в» / «Состоит из»);
- формат ссылок между строками (имя, код, GUID);
- признак корневого элемента;
- известные «грязные» места: объединённые ячейки, скрытые строки, примечания, дубли имён.

## 2. Описание структуры ЖЦ ОКС по ГОСТ Р 10.00.00.05-2025.docx (источник: «Описание»)

**ЗАПОЛНИТЬ**: как устроен документ — нумерация разделов, где описаны атрибуты, как связаны с типами из «Схемы», где брать бизнес-логику.

## 3. Макет таблицы для модуля.xlsx (цель импорта)

Колонки листа «Типы» (зафиксированы в промте v7.13, п. 5):

1. Системное имя
2. Видимое имя
3. Может быть корневым
4. Может монтироваться
5. Отображается на диске
6. Является проектом
7. Является документом
8. Умные папки
9. Служебный
10. Доп. параметры
11. Состоит из
12. Входит в

Колонки листа «Атрибуты»: **ЗАПОЛНИТЬ**.

## 4. Образцы для тестов (samples/)

- `samples/Структура_sample.csv` — 5–10 обезличенных строк, покрывающих все случаи (корень, обычный элемент, ссылка на справочник);
- `samples/Описание_sample.md` — фрагмент документа с описанием одного атрибута;
- `samples/Макет_sample.csv` — 1–2 строки целевой таблицы.

Правило: агенты пишут и проверяют код по разделам 1–4, реальные файлы не запрашивают.
